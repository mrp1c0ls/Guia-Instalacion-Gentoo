Capítulo 39 · Instalación de Gentoo

Acceso remoto por shell (SSH)

Paso opcional — habilita el servidor SSH para administrar tu equipo desde otra máquina
¿Para qué sirve este capítulo? Configura tu Gentoo para aceptar conexiones remotas por SSH desde el primer arranque, en vez de que solo puedas usarlo sentado frente al teclado/monitor.

🧩 El concepto en simple

El paquete que hace esto posible es net-misc/openssh, y ya viene instalado en el sistema base de Gentoo. El problema es que estar instalado no significa que arranque solo: en Gentoo, cada servicio debe registrarse explícitamente para iniciar con el sistema.

Este capítulo simplemente le dice a OpenRC: "cuando el sistema arranque, enciende también el servidor SSH (sshd)".

⚙️ Dónde se configura

ElementoUbicación
Registrar el servicio para que arranquerc-update (comando, no archivo)
Configuración del servidor SSH/etc/ssh/sshd_config
Consola serial (caso especial)/etc/inittab
Llaves del servidor (host keys)/etc/ssh/

🚀 Activar el servicio Riesgo bajo

Para qué sirve: agrega sshd al runlevel default, que es el conjunto de servicios que arrancan en un uso normal del sistema (equivalente a "modo multiusuario"). 
rc-update add sshd default

Es exactamente el mismo patrón que usaste con chronyd o el logger del sistema: rc-update add <servicio> <runlevel>. En NixOS sería el equivalente a services.openssh.enable = true;, solo que aquí es un comando en vez de una declaración en un archivo.

Para verificar que quedó registrado:

rc-update show | grep sshd

Y si quieres probarlo sin reiniciar (útil incluso durante la instalación, dentro del entorno live):

rc-service sshd start

🔐 Comportamiento por defecto y seguridad

Importante: por defecto sshd no permite login como root. Necesitas un usuario normal ya creado (o crear uno) antes de poder conectarte remotamente.

Esto es intencional: reduce el riesgo de que alguien intente forzar el acceso directamente a la cuenta con más privilegios del sistema.

¿Cómo permitir root por SSH? (no recomendado)

Si por alguna razón necesitas permitirlo (por ejemplo, en un entorno de pruebas aislado), se edita:

nano /etc/ssh/sshd_config

Y se ajusta la directiva PermitRootLogin (valores comunes: no, yes, prohibit-password). Después hay que reiniciar el servicio para que el cambio tome efecto:

rc-service sshd restart

📡 Caso especial: consola serial

Esto solo aplica si tu equipo es un servidor sin monitor que administras a través de un puerto serie (poco común en un equipo de escritorio). Si no es tu caso, puedes ignorar esta sección.

Configurar agetty en consola serial 
nano -w /etc/inittab

Se descomentan las líneas de la sección SERIAL CONSOLES:

s0:12345:respawn:/sbin/agetty 9600 ttyS0 vt100
s1:12345:respawn:/sbin/agetty 9600 ttyS1 vt100

🖥️ Referencia: equivalente en systemd

Solo para contraste, ya que tu instalación usa OpenRC — no necesitas ejecutar esto:

systemctl enable sshd

✨ Vale la pena saber (no está en el manual, pero es útil)

La primera conexión mostrará una "huella digital" (fingerprint)

La primera vez que te conectes por SSH a tu Gentoo recién instalado, el cliente SSH te pedirá confirmar la huella del servidor. Es normal — solo verifica que estás conectando al equipo correcto.

Si reinstalas el sistema, tu cliente SSH se quejará

Cuando reinstales Gentoo (mismo disco, mismo hostname/IP), tu computadora cliente pensará que alguien está suplantando al servidor, porque las llaves cambiaron. Hay que borrar la entrada vieja con:

ssh-keygen -R <ip-o-hostname>

Opciones útiles en sshd_config

DirectivaQué controla
PortPuerto de escucha (por defecto 22)
PermitRootLoginSi root puede entrar directamente
PasswordAuthenticationPermitir login con contraseña vs. solo llaves
AllowUsersLista blanca de usuarios que pueden conectarse

Cualquier cambio en este archivo requiere rc-service sshd restart para aplicarse.

✅ Resumen rápido

Qué hacer

  • rc-update add sshd default
  • Crear un usuario no-root para conectarte
  • (Opcional) probar con rc-service sshd start

Cuándo saltarlo

  • Si vas a trabajar solo desde el teclado/monitor local
  • Se puede activar después del primer arranque sin problema
