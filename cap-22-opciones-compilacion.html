Capítulo 22 — Configurando las opciones de compilación

Qué son las variables de compilación, para qué sirven y cómo configurarlas correctamente en make.conf.

¿Dónde se configura todo esto?
Todo lo de este capítulo va en un solo archivo: /mnt/gentoo/etc/portage/make.conf (dentro del chroot, simplemente /etc/portage/make.conf). Este archivo lo lee Portage cada vez que compila cualquier paquete, así que los cambios aquí afectan a todo el sistema, no solo a la instalación inicial. 
root # nano /mnt/gentoo/etc/portage/make.conf

Para qué sirve: abre el archivo de configuración principal de Portage con el editor nano para poder editar las variables.

1. CFLAGS y CXXFLAGS — compilador de C y C++

Le dicen a GCC (el compilador) cómo optimizar el código de cada programa en C (CFLAGS) y C++ (CXXFLAGS) al momento de compilarlo.

COMMON_FLAGS="-march=native -O2 -pipe"
CFLAGS="${COMMON_FLAGS}"
CXXFLAGS="${COMMON_FLAGS}"

Para qué sirve: define una sola vez el conjunto de flags (COMMON_FLAGS) y lo reutiliza en ambos compiladores, para no repetir código.

Flags disponibles y qué hace cada una

FlagQué haceRecomendación
-march=nativeOptimiza el código para el CPU exacto de la máquina donde compilas.✅ Uso común
-march=x86-64-v2 / v3 / v4Optimiza para un nivel de instrucciones x86-64 genérico (útil si el binario correrá en otra máquina distinta).Alternativa a native
-mtune=nativeAjusta solo el "tuning" (orden de instrucciones), sin exigir instrucciones exclusivas del CPU. Más portable que -march.Opcional
-pipeUsa memoria RAM en vez de archivos temporales entre etapas del compilador. Compila algo más rápido.RAM baja: evitar
-fomit-frame-pointerLibera un registro extra del CPU al no guardar el "frame pointer".Dificulta depuración

Niveles de optimización -O (letra O, no cero)

FlagQué significa
-O0Sin optimizar. Compila rápido, el programa corre lento. Útil solo para depurar.
-O1Optimizaciones básicas, seguras.
-O2Recomendado por el handbook. Buen balance velocidad/estabilidad.
-O3Máxima optimización de velocidad. Puede causar bugs en algunos paquetes si se usa en todo el sistema.
-OsOptimiza para tamaño del binario, no velocidad. Útil en discos/RAM muy limitados.
-OgOptimización mínima pensada para depurar con buena información de debug.
Advertencia del handbook: no metas flags experimentales aquí. Demasiada optimización puede hacer que los programas se comporten mal (crasheen o, peor, funcionen mal silenciosamente). Los valores por defecto que trae el stage3 ya son suficientemente buenos si no quieres tocar nada.

2. RUSTFLAGS — compilador de Rust

Es independiente de CFLAGS/CXXFLAGS: cada variable solo afecta al compilador de su propio lenguaje. Rust ya optimiza a nivel 3 por defecto, así que lo único que vale la pena añadir es la optimización para tu CPU específico:

RUSTFLAGS="${RUSTFLAGS} -C target-cpu=native"

Para qué sirve: el ${RUSTFLAGS} al inicio conserva cualquier valor previo (por ejemplo, del profile de Gentoo) y le agrega -C target-cpu=native al final, en vez de sobrescribirlo.

root # rustc -C target-cpu=help

Para qué sirve: muestra la lista de CPUs que Rust reconoce, y cuál sería seleccionado con native en tu máquina.

Si dejas solo RUSTFLAGS sin tocar CFLAGS/CXXFLAGS, el sistema compila sin problema: los paquetes en Rust quedan optimizados a tu CPU, y los de C/C++ usan los valores por defecto del stage3.

3. MAKEOPTS — compilación en paralelo

Controla cuántos procesos de compilación corren al mismo tiempo.

MAKEOPTS="-j4 -l5"
FlagQué controla
-j4Techo fijo: máximo 4 compilaciones en paralelo.
-l5Freno dinámico: si el load average (carga del sistema) llega a 5, no lanza más procesos, aunque -j deje margen.

Regla práctica: usa el menor valor entre el número de hilos (nproc) de tu CPU, o tu RAM total dividida entre 2 GiB.

Sobre la memoria: no existe un flag de MAKEOPTS que limite RAM directamente (no hay un -mMemoria). La memoria se controla indirectamente bajando -j: menos procesos en paralelo = menos memoria usada a la vez. Regla del handbook: al menos 2 GiB de RAM por cada job (-j6 requiere mínimo 12 GiB).
¿Y si necesito un límite duro de memoria? Avanzado

Portage/make no lo ofrecen de forma nativa. Se lograría con herramientas externas del sistema como cgroups o systemd-run --scope -p MemoryMax=..., fuera del alcance de este capítulo.

Resumen: qué escribir al final

COMMON_FLAGS="-march=native -O2 -pipe"
CFLAGS="${COMMON_FLAGS}"
CXXFLAGS="${COMMON_FLAGS}"
RUSTFLAGS="${RUSTFLAGS} -C target-cpu=native"
MAKEOPTS="-j4 -l5"

Guarda con Ctrl+O y sal con Ctrl+X (en nano). Con esto, el capítulo 22 queda listo para pasar al capítulo 24 (Chrooting) — el 23 son solo referencias.
