Capítulo 15 · Particionar el disco con GPT para UEFI

Guía práctica con fdisk para crear la ESP, la swap y la partición raíz — Manual de instalación de Gentoo AMD64

¿Qué se hace en este capítulo?

Aquí dejamos la teoría atrás y ejecutamos los comandos reales para dividir el disco en tres particiones usando fdisk, que funciona como un pequeño programa interactivo: lo abres, respondes preguntas de una letra, y al final confirmas para escribir los cambios de verdad.

ParticiónPunto de montajeSistema de archivosFunción
/dev/sda1/efivfat (FAT32)ESP — donde el firmware UEFI busca el arrancador
/dev/sda2—swapMemoria de intercambio en disco
/dev/sda3/xfs (o el que elijas)Raíz del sistema
⚠️ Antes de empezar Todo lo que se escribe dentro de fdisk queda solo en memoria hasta presionar w. Pero una vez que guardas, cualquier dato previo en esas particiones se pierde. Confirma que /dev/sda es el disco correcto (usa lsblk antes de entrar) — sobre todo si hay más de un disco conectado.

Comandos paso a paso

riesgo bajo
root # fdisk /dev/sda

Para qué sirve: abre el disco en modo interactivo. No modifica nada todavía; es seguro entrar y salir sin guardar.

riesgo bajo
Command (m for help): p

Para qué sirve: imprime la tabla de particiones actual (tamaño del disco, tipo de disklabel, particiones existentes). Úsalo para verificar antes y después de cada cambio.

riesgo medio
Command (m for help): g

Para qué sirve: crea una tabla de particiones GPT nueva y vacía. Si el disco ya tiene una GPT que quieres conservar, en vez de esto borra particiones una por una con d.

riesgo medio
Command (m for help): n
Partition number (1-128, default 1): 1
First sector: [Enter]
Last sector: +1G
Command (m for help): t
Partition type or alias: 1

Para qué sirve: crea la partición 1 (1 GiB) y la marca como EFI System. Esta es la ESP; sin marcarla correctamente el firmware UEFI no encontrará el arrancador.

riesgo medio
Command (m for help): n
Partition number (2-128, default 2): 2
First sector: [Enter]
Last sector: +4G
Command (m for help): t
Partition type or alias: 19

Para qué sirve: crea la partición 2 como swap (aquí 4 GiB de ejemplo — ajusta el tamaño a tu RAM y necesidades). El tipo 19 es el alias de "Linux swap" en fdisk moderno.

riesgo medio
Command (m for help): n
Partition number (3-128, default 3): 3
First sector: [Enter]
Last sector: [Enter]

Para qué sirve: crea la partición 3 usando todo el espacio restante del disco — será la raíz (/). Dejar el "last sector" en blanco le dice a fdisk que use todo lo que sobra.

riesgo alto
Command (m for help): w

Para qué sirve: escribe la tabla de particiones al disco físico y sale. Es el único paso que realmente modifica el disco — hasta este momento puedes salir con q sin guardar nada.

¿Qué es cada tecla que usamos dentro de fdisk?
  • p — imprimir (print) la tabla de particiones actual
  • g — crear un disklabel GPT nuevo
  • n — nueva partición (new)
  • d — borrar partición (delete)
  • t — cambiar el tipo de una partición
  • w — escribir cambios y salir (write)
  • q — salir sin guardar nada (quit)
  • m — mostrar la ayuda con todos los comandos
¿Por qué el tipo de la partición raíz no es obligatorio?

El manual aclara que marcar la partición 3 como "Linux root (x86-64)" (tipo 23) es opcional. El sistema arranca igual si queda como "Linux filesystem" genérico. Ese tipo específico solo es necesario si usas un bootloader que lo requiere para identificar la raíz sin depender de /etc/fstab — por ejemplo systemd-boot. Como en tu instalación usarás GRUB, no es indispensable, pero no hace daño marcarlo igual.

Alternativa: parted (no cubierta en el manual, pero existe)

parted es otra herramienta de particionado disponible en el medio de instalación, capaz de manejar GPT desde sus inicios. El manual prefiere fdisk por ser más estándar y estar disponible en casi cualquier entorno Linux, pero si alguna vez ves guías que usan parted, es simplemente una alternativa con la misma finalidad.

📝 Verificación recomendada (no es parte oficial del capítulo) Antes de continuar con el siguiente capítulo (crear los sistemas de archivos), es buena práctica confirmar que las tres particiones quedaron como se esperaba: 
root # lsblk /dev/sda
root # blkid
lsblk muestra el árbol de particiones y tamaños; blkid muestra los UUID y tipos de sistema de archivos (aunque en este punto todavía no tienen filesystem, solo tipo de partición).
➡️ Qué sigue Con las particiones creadas pero todavía vacías, el siguiente paso (Capítulo 17 del manual) es formatearlas con mkfs.vfat, mkswap y mkfs.xfs (u otro filesystem elegido) para que realmente puedan almacenar datos.
