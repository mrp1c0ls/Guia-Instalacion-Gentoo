Capítulo 12: Configuración manual de red con IP estática

Handbook de Gentoo AMD64 — Sección de instalación / redes

Este capítulo aplica en la práctica lo visto en la teoría de redes (interfaces, CIDR, rutas y DNS). Aquí se configura a mano una IP fija, la ruta de salida a internet y el servidor DNS, todo desde el medio de instalación en vivo — es decir, es temporal, sirve solo para tener internet mientras instalas. La configuración permanente del sistema final se hace más adelante (con netifrc o systemd-networkd).

1. IP local → 2. Ruta por defecto → 3. DNS → Internet funcionando

12.1 Configurar la dirección IP de la interfaz

Le asignas una dirección IP a tu tarjeta de red (aquí enp1s0) usando el comando ip, parte del paquete sys-apps/iproute2.

root # ip address add 192.168.0.2/24 dev enp1s0
Para qué sirve: le da identidad a tu equipo dentro de la red local. Sin esto, nadie puede "verte" en la red.
RIESGO BAJO — es completamente reversible, solo se pierde al reiniciar (vive en memoria, no se guarda en disco).
Cuidado: la IP se pone a mano, así que puede chocar con la de otro dispositivo ya conectado a la red (conflicto de IP). Revisa que el número que elijas esté libre.
Atajo: ip a es lo mismo que ip address.

12.2 Configurar la ruta por defecto (gateway)

Con solo el paso anterior, tu equipo ya puede hablar con otros dispositivos de la misma red local, pero no con internet. Falta decirle cuál es la "puerta de salida" (normalmente tu router).

root # ip route add default via 192.168.0.1
Para qué sirve: le dice al sistema "todo el tráfico que no sea para mi red local, mándalo por aquí" — es la puerta hacia internet.

Para revisar qué rutas están activas:

root # ip route
Atajo: ip r es lo mismo que ip route.

12.3 Configuración de DNS

El DNS traduce nombres como gentoo.org a direcciones IP. En Linux se define en /etc/resolv.conf.

root # nano /etc/resolv.conf
Para qué sirve: abre el archivo donde defines qué servidores DNS usar, para poder navegar por nombre y no solo por IP.

Dentro se agregan líneas nameserver (se consultan en el orden en que aparecen):

ProveedorContenido del archivo
Cloudflarenameserver 1.1.1.1
nameserver 1.0.0.1
Quad9nameserver 9.9.9.9
nameserver 149.112.112.112
Cuidado: si dhcpcd está corriendo, va a sobrescribir tus cambios a resolv.conf automáticamente. Verifica primero con ps x | grep dhcpcd.

Para confirmar que todo funciona:

root # ping -c 3 gentoo.org
Para qué sirve: si responde, tienes IP, ruta y DNS funcionando al mismo tiempo — luz verde para seguir con la partición de discos.

Extra: diagnóstico rápido si algo falla

El handbook lo menciona disperso en capítulos anteriores, pero conviene tenerlo junto como checklist de diagnóstico:

ComandoQué revisa
ping -c 3 1.1.1.1Conectividad básica a internet (por IP, sin depender de DNS)
curl --location gentoo.org --output /dev/nullAcceso HTTPS + que el DNS resuelva nombres
ip linkSi la interfaz de red existe y está activa (UP)
Lógica de diagnóstico: si el ping a 1.1.1.1 funciona pero curl a gentoo.org falla, el problema es DNS, no la conexión. Aísla el problema por partes en vez de adivinar.
¿Por qué esta config no sobrevive un reinicio?

Los comandos ip address e ip route modifican la configuración de red en memoria (kernel), no escriben nada en disco. Es ideal para el entorno live de instalación, pero para que la IP estática persista en el sistema ya instalado, se necesita configurarla en /etc/conf.d/net (con netifrc en OpenRC) o en un archivo .network (con systemd-networkd), pasos que se ven en capítulos posteriores del proceso de instalación.

Repaso relámpago de CIDR (¿por qué /24?)

/24 equivale a la máscara 255.255.255.0 y define cuántos equipos caben en la red: 254 direcciones usables. Es el tamaño más común para redes domésticas y de laboratorio. La fórmula general es 2^(32-CIDR) - 2.
