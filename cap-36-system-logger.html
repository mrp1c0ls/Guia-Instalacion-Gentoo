Capítulo 36 — System Logger

Elegir y activar el registrador de eventos del sistema (perfil OpenRC)

¿Qué es y por qué el stage3 no trae uno?

El system logger es el servicio que guarda en archivos (normalmente dentro de /var/log/) todo lo que va pasando en el sistema: errores, advertencias, eventos de arranque, intentos de acceso, etc. Sin él, esos mensajes se pierden apenas se generan.

Gentoo no incluye ninguno por defecto en el stage3 porque existen varios paquetes que hacen lo mismo con distinto enfoque, y prefiere que el usuario elija el que le conviene en vez de imponer uno.

Analogía NixOS: es como declarar services.journald o cualquier otro logger en configuration.nix — nada corre "gratis" sin que lo pidas explícitamente en el sistema.

Opciones disponibles

Paquete Perfil Rotación de logs Notas
app-admin/sysklogd Principiante recomendado Sí (incluida, v2.0+) Funciona bien "tal cual", sin configurar nada extra.
app-admin/syslog-ng Avanzado No — requiere logrotate aparte Muy potente, pero necesita configuración manual para sacarle provecho.
app-admin/metalog Avanzado Configurable Altamente personalizable, orientado a filtrado fino de mensajes.
Para qué sirve elegir bien Si sólo quieres logs funcionando sin complicarte, sysklogd es la elección estándar del handbook para principiantes. Si más adelante necesitas reenviar logs a un servidor central o filtrar mensajes por reglas complejas, ahí es cuando syslog-ng o metalog valen la pena.

Instalación y activación (sysklogd)

Corre en chroot, como root

1. Instalar el paquete bajo riesgo

root # emerge --ask app-admin/sysklogd
Para qué sirve Descarga y compila (o instala binario, si configuraste binhost) el logger. El flag --ask te muestra qué se va a instalar y pide confirmación antes de proceder — es "emerger", es decir, reversible: si te arrepientes, luego lo desinstalas sin dejar el sistema en mal estado.

2. Activarlo en el arranque bajo riesgo

root # rc-update add sysklogd default
Para qué sirve Instalar el paquete no lo hace arrancar solo. rc-update add es el comando de OpenRC que registra el servicio en un runlevel (aquí, default, el que se activa en un arranque normal). Sin este paso, sysklogd quedaría instalado pero apagado.
Comandos útiles después de instalarlo
ComandoQué hace
rc-service sysklogd startLo arranca de inmediato (sin esperar el próximo reboot).
rc-service sysklogd statusMuestra si está corriendo.
tail -f /var/log/messagesVer los logs en vivo mientras se generan.
rc-update showLista todos los servicios y en qué runlevel están activos.
¿Y si prefiero syslog-ng o metalog?

El patrón es idéntico, solo cambia el nombre del paquete y del servicio:

root # emerge --ask app-admin/syslog-ng
root # rc-update add syslog-ng default
Advertencia Si eliges syslog-ng, instala también app-admin/logrotate — de lo contrario el archivo de log crecerá indefinidamente sin rotarse ni comprimirse.

Dónde vive todo esto

Binario / servicio /etc/init.d/sysklogd
Configuración /etc/syslog.conf
Salida de logs /var/log/messages, /var/log/syslog

El archivo /etc/syslog.conf define qué se registra y dónde: por ejemplo, puedes mandar solo los mensajes críticos del kernel a un archivo separado. Para un sistema doméstico, la configuración por defecto suele ser suficiente y no hace falta tocarla.

Referencia: si usaras systemd

No aplica a tu instalación (usas OpenRC), pero para completar el panorama: los sistemas con systemd ya traen systemd-journald integrado, que cubre casi toda la funcionalidad de un logger tradicional. La mayoría de esas instalaciones se saltan por completo este paso. Para consultar esos logs se usa journalctl en vez de leer archivos de texto plano.
