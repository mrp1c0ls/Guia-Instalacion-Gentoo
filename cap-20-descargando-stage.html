Capítulo 20 — Descargando el archivo stage

Ajustar el reloj del sistema, obtener el stage file y verificar que llegó íntegro y sin alteraciones.

Para qué sirve este capítulo Antes de instalar el sistema base necesitas dos cosas: que el reloj del equipo esté sincronizado (o las descargas por HTTPS pueden fallar) y descargar el archivo stage3 correcto — la "semilla" de tu futuro sistema Gentoo. Este capítulo cubre ambos pasos, más la verificación de que el archivo no viene corrupto ni manipulado.

1. Ajustar la fecha y hora

Las descargas usan HTTPS, que depende de certificados con fecha de validez. Si el reloj del live environment está muy desfasado, la descarga puede fallar de forma confusa.

Revisar la hora actual Bajo riesgo 
root # date

Si el resultado está a más de unos minutos de diferencia con la hora real, corrígelo.

Opción automática — chrony Recomendada

Sincroniza el reloj vía NTP contra servidores de internet. Es la forma más confiable:

root # chronyd -q
Nota El tráfico NTP estándar no está autenticado — es información pública, no un canal seguro, pero suficiente para este propósito.
Opción manual — sin acceso a NTP Bajo riesgo

Formato: MMDDhhmmYYYY (mes, día, hora, minuto, año). Ejemplo, 3 de octubre 13:16 del 2021:

root # date 100313162021

Se recomienda usar hora UTC; la zona horaria real se configura después (Capítulo 27).

2. Descargar el stage file

Ya elegiste el tipo de stage (multilib + OpenRC, en tu caso) en el capítulo anterior. Ahora solo falta bajarlo.

Con navegador gráfico Más simple

Copias el enlace desde la página de descargas de Gentoo y lo pegas en wget:

root # wget <URL_DEL_STAGE_FILE>
Con navegador de texto (sin entorno gráfico)

Puedes navegar los mirrors directamente desde la terminal con links o lynx:

root # links https://www.gentoo.org/downloads/mirrors/

Navegas a releases/amd64/autobuilds/, eliges el stage correcto y presionas d para descargar.

Si necesitas proxy:

root # export http_proxy="http://proxy.server.com:port"

3. Verificar y validar el archivo Importante

Para qué sirve Confirma que el archivo descargado no está corrupto y que realmente lo publicó el equipo de Gentoo, no un tercero que lo alteró en el camino.
ArchivoQué contiene
.CONTENTS.gzLista de todos los archivos dentro del stage.
.DIGESTSChecksums del archivo en varios algoritmos (SHA256, SHA512, BLAKE2B).
.sha256Checksum SHA256 firmado con PGP (no siempre disponible).
Verificar la firma criptográfica (GPG)

Primero importa la llave pública de Gentoo (si no lo hiciste ya en el Capítulo 4):

root # gpg --import /usr/share/openpgp-keys/gentoo-release.asc

Luego verifica la firma:

root # gpg --verify stage3-amd64-<release>-<init>.tar.xz.asc stage3-amd64-<release>-<init>.tar.xz

Si todo está bien, el resultado incluirá la línea Good signature from.

Verificar el checksum (alternativa/complemento) 
root # sha256sum --check stage3-amd64-<release>-<init>.tar.xz.sha256.verified

Debe imprimir OK. Si dice FAILED, el archivo está corrupto o alterado — descártalo y vuelve a descargar.

Si algo falla Nunca continúes la instalación con un stage file que no pasó la verificación. Un archivo corrupto puede causar errores difíciles de diagnosticar mucho más adelante en el proceso.

Contexto extra: ¿por qué existe este paso?

Un stage file es un archivo comprimido (.tar.xz) que contiene un sistema Gentoo casi completo — la base sobre la que se construye todo lo demás. Se genera con una herramienta interna de Gentoo llamada Catalyst y se actualiza con frecuencia, por eso no viene incluido en el medio de instalación y hay que descargarlo aparte.

La verificación con GPG y checksums no es paranoia innecesaria: es el mismo principio que usaste al verificar el ISO de instalación en el Capítulo 4. Es la única garantía de que lo que vas a extraer en /mnt/gentoo es exactamente lo que Gentoo publicó.

Siguiente paso Con el stage file descargado y verificado, el Capítulo 21 lo extrae dentro de /mnt/gentoo con tar, y el Capítulo 22 configura las opciones de compilación (make.conf) antes de entrar al chroot.
