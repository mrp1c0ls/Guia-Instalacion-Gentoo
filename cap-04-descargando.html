Capítulo 4 — Descargando

Manual de instalación de Gentoo (AMD64) · Resumen sencillo

Este capítulo trata de dos cosas: conseguir el archivo de instalación (la imagen ISO) y comprobar que ese archivo es real y no está dañado antes de usarlo. Todavía no se instala nada — es la etapa de preparación.

4.1 — Obtener el medio de instalación

Se descarga la imagen .iso desde los servidores espejo ("mirrors") de Gentoo. Junto a ella aparecen otros archivos que la acompañan:

ArchivoPara qué sirve
.isoEl medio de instalación en sí (lo que se graba en el USB).
.iso.ascFirma digital del ISO — sirve para comprobar que es auténtico.
.CONTENTS.gzLista comprimida de todo lo que trae el ISO (drivers, firmware, etc.).
.DIGESTSChecksums (huellas) del archivo en varios algoritmos (SHA256, SHA512, BLAKE2B).
.sha256Checksum SHA256 firmado con PGP (no siempre disponible).
Navegar los mirrors manualmente

Si no se usa el enlace directo de descarga, el recorrido típico dentro del mirror es:

  1. Elegir un mirror cercano.
  2. Entrar a releases/
  3. Entrar a la arquitectura, por ejemplo amd64/
  4. Entrar a autobuilds/
  5. Elegir current-install-amd64-minimal/ y descargar el .iso

También se puede usar un navegador de texto como links o lynx desde una terminal, útil en entornos sin interfaz gráfica.

4.2 — Verificar los archivos descargados Recomendado

Esto confirma dos cosas: que el archivo no se corrompió durante la descarga y que de verdad lo publicó el equipo de Gentoo (no fue alterado por un tercero).

Idea clave: el archivo .asc es una "firma" hecha con la clave privada de Gentoo. Solo Gentoo puede crearla, pero cualquiera puede comprobarla con su clave pública. Si la firma coincide, el archivo es legítimo.

En Windows

Se usa un programa como GPG4Win. Se importan las claves públicas de Gentoo (disponibles en su página oficial de firmas) y luego se verifica el .iso contra su .asc.

En Linux

Se usa gnupg. El flujo básico:

# 1. Importar la clave pública de Gentoo
gpg --keyserver hkps://keys.gentoo.org --recv-keys 13EBBDBEDE7A12775DFDB1BABB572E0E2D182910

# 2. Verificar la firma del ISO
gpg --verify install-amd64-minimal-<fecha>.iso.asc install-amd64-minimal-<fecha>.iso

Si todo está bien, aparece Good signature from... Es importante comparar el fingerprint (huella) mostrado con el publicado en la web oficial, para confirmar que la clave usada es realmente de Gentoo y no una falsificación.

Alternativa: verificar solo el checksum (sin GPG)

Si no se quiere usar GPG, también se puede comprobar la integridad del archivo (que no esté corrupto) comparando su huella con la del archivo .DIGESTS o .sha256, usando herramientas como sha256sum u openssl. 

sha256sum --check install-amd64-minimal-<fecha>.iso.sha256

Diferencia importante: el checksum solo detecta descargas dañadas; no garantiza que el archivo sea auténtico. Para eso hace falta la firma GPG.

Tabla comparativa: checksum vs. firma GPG

Método¿Qué comprueba?¿Detecta manipulación maliciosa?
Checksum (SHA256, etc.)Que el archivo llegó completo y sin errores❌ No
Firma GPG (.asc)Que el archivo lo publicó realmente Gentoo✅ Sí
Recomendación práctica: si es la primera vez, basta con el checksum para descartar una descarga corrupta. Para mayor seguridad (por ejemplo, en una red pública o si el archivo se bajó de un mirror poco conocido), conviene verificar también la firma GPG.

¿Qué sigue después de este capítulo?

Una vez descargado y verificado el ISO, el siguiente paso (Capítulo 5) es escribirlo en un medio de arranque — usualmente un USB con dd en Linux, o herramientas como Rufus en Windows (evitando programas como Ventoy, que el manual advierte que pueden causar fallos de arranque).
