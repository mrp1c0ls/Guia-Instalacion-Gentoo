Capítulo 37 — Cron Daemon

Automatización de tareas programadas en tu sistema

En una frase

Un cron daemon es un programa que corre en segundo plano y ejecuta comandos automáticamente según un horario que tú definas (cada hora, cada día, cada semana...). En Gentoo, con OpenRC, la opción recomendada y más sencilla es cronie.

¿Qué problema resuelve?

Hay tareas de mantenimiento que un sistema necesita hacer con regularidad: limpiar archivos temporales, actualizar bases de datos, respaldar información, sincronizar algo, etc. En lugar de acordarte tú de ejecutarlas manualmente, un cron daemon lo hace por ti, con la periodicidad que definas.

¿Para qué sirve? Automatizar tareas repetitivas del sistema sin intervención humana. Es la pieza que le falta a tu servidor/PC para "acordarse" de hacer mantenimiento por sí mismo.
¿Dónde se configura? El horario de las tareas vive en archivos llamados crontabs. El más importante para el sistema es /etc/crontab (tareas a nivel sistema, ejecutadas por root u otros usuarios especificados en el propio archivo). Cada usuario también puede tener su propio crontab personal, editable con crontab -e, y que normalmente se guarda internamente en /var/spool/cron/crontabs/<usuario> (la ubicación exacta depende del demonio elegido).

Las 4 opciones disponibles en Gentoo

Todas cumplen la misma función básica (ejecutar comandos programados), pero difieren en filosofía: seguridad, simplicidad o funciones extra.

DemonioPaqueteEnfoque¿Cuándo elegirlo?
cronie (default) sys-process/cronie El cron "clásico" (basado en Vixie cron) con mejoras de seguridad: soporta PAM y SELinux. Uso general. Es la opción recomendada por el manual y la más compatible/documentada.
dcron sys-process/dcron Minimalista: simple y seguro, solo lo esencial. Sistemas donde quieres el mínimo software posible corriendo.
fcron sys-process/fcron Extiende cron con capacidades tipo anacron (ejecuta tareas perdidas si el equipo estuvo apagado). Laptops o equipos que no están encendidos 24/7 y no quieres perder tareas programadas.
bcron sys-process/bcron Diseño moderno centrado en seguridad: divide responsabilidades en varios procesos pequeños con comunicación controlada entre ellos. Entornos donde el aislamiento/seguridad de procesos es prioridad.

Instalación y uso — opción por defecto: cronie

Instalar el paquete
root # emerge --ask sys-process/cronie
Riesgo bajo
Qué hace: descarga, compila e instala cronie. --ask te muestra qué se va a instalar antes de confirmar.
Activar el servicio en el arranque
root # rc-update add cronie default
Riesgo bajo — reversible
Qué hace: agrega el servicio cronie al runlevel default de OpenRC, para que arranque automáticamente cada vez que enciendas el sistema. Sin esto, cronie no se ejecutaría a menos que lo inicies manualmente con rc-service cronie start cada vez.

¿Y cómo le doy tareas para que ejecute?

Aquí hay dos caminos, según quién debe ejecutar la tarea:

Opción 1 — Crontab del sistema: /etc/crontab

Se edita directamente como root y permite especificar qué usuario ejecuta cada línea. Formato:

minuto hora día-mes mes día-semana usuario  comando

Ejemplo — ejecutar un script cada día a las 3:00 AM como root:

0 3 * * * root /usr/local/bin/mi_backup.sh

Los campos aceptan * (cualquier valor), rangos (1-5), listas (1,15) y saltos (*/6 = cada 6 unidades).

Opción 2 — Crontab personal de un usuario: crontab -e

Cada usuario (incluido root) puede tener su propio crontab, sin necesidad de indicar el usuario en cada línea (ya se sabe de quién es):

$ crontab -e      # abre tu crontab personal en el editor
$ crontab -l      # lista tus tareas programadas actuales
$ crontab -r      # elimina tu crontab (¡cuidado, sin confirmación!)
Riesgo medio — crontab -r borra todo sin preguntar

Alternativas: pasos de instalación específicos

dcron — requiere inicialización manual 
root # emerge --ask sys-process/dcron
root # crontab /etc/crontab

El segundo comando es necesario porque dcron, a diferencia de cronie, no lee /etc/crontab automáticamente — hay que "cargarlo" explícitamente la primera vez.

fcron — requiere paso de configuración post-emerge 
root # emerge --ask sys-process/fcron
root # emerge --config sys-process/fcron

emerge --config ejecuta un script de configuración interactivo que trae el propio paquete (no todos los paquetes lo requieren, pero fcron sí). Esto suele encargarse de crear las estructuras internas que fcron necesita para funcionar correctamente.

bcron — instalación simple, sin pasos extra 
root # emerge --ask sys-process/bcron

El manual no indica pasos adicionales de activación para bcron más allá de la instalación estándar.

Caso especial: usuarios de modprobed-db

Si compilaste tu kernel manualmente (en vez de usar gentoo-kernel con configuración automática) y usaste la herramienta modprobed-db para detectar qué módulos usa tu hardware, aquí se programa que escanee el sistema periódicamente.

Agregar a /etc/crontab
# Ejecutar modprobed-db cada 6 horas
0 */6 * * * /usr/bin/modprobed-db store &> /dev/null
Riesgo bajo
Nota: como en tu instalación usas sys-kernel/gentoo-kernel, esta sección probablemente no te aplica — es relevante solo para quienes compilan el kernel a mano y usan esa herramienta de detección de módulos.

Verificar que todo funciona

Confirmar que el servicio está corriendo
root # rc-service cronie status
Revisar los logs de ejecución de cron
root # tail -f /var/log/cron.log

La ruta exacta del log puede variar según el logger del sistema que instalaste (sysklogd, syslog-ng, etc. — capítulo 36).

Si usaras systemd (referencia)

systemd no necesita un cron daemon aparte: trae timers integrados, que cumplen la misma función (ejecutar servicios en horarios programados) mediante unidades .timer. Para la mayoría de instalaciones systemd, instalar un cron adicional es innecesario — solo se justifica si necesitas compatibilidad específica con sintaxis crontab tradicional.

Resumen rápido

  • Qué es: un programa que ejecuta comandos en horarios definidos.
  • Recomendado: cronie — simple, seguro, compatible.
  • Se configura en: /etc/crontab (sistema) o crontab -e (por usuario).
  • Para activarlo en el arranque: rc-update add cronie default.
  • Alternativas: dcron (ligero), fcron (recupera tareas perdidas), bcron (seguridad por diseño).
