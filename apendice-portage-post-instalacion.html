1. ¿Qué es emerge?

emerge es el gestor de paquetes de Portage: resuelve dependencias, descarga fuentes (o binarios), compila e instala. Es el único comando que necesitas para el 90% del mantenimiento diario del sistema.

Para qué sirve: es el punto de entrada único para instalar, actualizar, desinstalar, buscar y limpiar software. Internamente lee /etc/portage/make.conf en cada invocación, además de todo lo que haya bajo /etc/portage/package.*/.

Sintaxis general:

emerge [opciones] <categoría/paquete | @conjunto>

El paquete se identifica como categoría/nombre (ej. www-client/firefox). Si el nombre no es ambiguo, puedes omitir la categoría. Un @conjunto (set) agrupa varios paquetes — el más importante es @world, la lista de todo lo instalado explícitamente.

2. Instalar paquetes

Ejemplo de instalación básica 
# Instalar un navegador
root # emerge --ask www-client/firefox

# Proceso que sigue Portage al ejecutarse:
# 1. Lee make.conf y package.* para conocer USE flags, keywords, masks
# 2. Calcula el árbol de dependencias del paquete pedido
# 3. Muestra el plan: qué se instala, con qué flags, tamaño de descarga
# 4. Espera confirmación (por --ask)
# 5. Descarga fuentes/binarios, compila si aplica, e instala
OpciónPara qué sirve
-a / --askMuestra el plan de acción y pide confirmación antes de tocar el sistema. Úsalo siempre.
-p / --pretendSimula: calcula el plan pero no ejecuta nada, ni siquiera pide confirmar.
-v / --verboseMuestra detalle extra: qué USE flags quedan activos/inactivos por paquete.
Diferencia clave: --pretend nunca ejecuta nada aunque no lo combines con --ask. --ask sí ejecuta, pero solo después de tu confirmación.

3. Actualizar el sistema (@world) riesgo medio

Portage no tiene un mecanismo de "generaciones" atómicas: actualiza paquete por paquete sobre el sistema en vivo. El objetivo de actualización casi siempre es @world, el conjunto de paquetes instalados explícitamente (más el @system base).

Ejemplo de actualización completa 
root # emerge --ask --verbose --update --deep --newuse @world

# Proceso:
# 1. Toma @world como punto de partida
# 2. --deep expande la revisión a TODO el árbol de dependencias, no solo directas
# 3. Compara versiones instaladas vs disponibles en el árbol sincronizado
# 4. --newuse detecta cambios de USE flags en make.conf/package.use desde la última compilación
# 5. Construye el plan de recompilación/actualización y lo muestra (por -v)
# 6. Tras confirmar, compila/instala en orden de dependencias
OpciónPara qué sirve
-u / --updateConsidera paquetes ya instalados como candidatos a actualizar (sin esto, solo instala lo que falta).
-D / --deepRevisa dependencias de forma recursiva y completa, no solo el primer nivel.
--newuseRecompila si cambiaron USE flags desde la última vez que se compiló el paquete.
--changed-useSimilar, pero solo si el cambio de USE afecta características ya compiladas (más selectivo, evita recompilaciones innecesarias).
-g / --getbinpkgPrefiere descargar binarios de un binhost configurado en vez de compilar desde fuente.

4. Sincronizar el árbol de ebuilds

Antes de instalar o actualizar, tu copia local de "recetas" (ebuilds) debe estar actualizada.

Ejemplo de sincronización 
root # emerge --sync

# Proceso:
# 1. Lee sync-type y sync-uri en /etc/portage/repos.conf/gentoo.conf
# 2. Descarga los cambios más recientes (rsync/git/webrsync según config)
# 3. Verifica firmas OpenPGP del snapshot (si sync-openpgp-key-path está definido)
# 4. Actualiza /var/db/repos/gentoo con el árbol nuevo
# 5. Anuncia "news items" pendientes si los hay

# Terminal lenta (framebuffer/serial):
root # emerge --sync --quiet
Configuración: /etc/portage/repos.conf/gentoo.conf 
[DEFAULT]
main-repo = gentoo

[gentoo]
location = /var/db/repos/gentoo
sync-type = rsync
sync-uri = rsync://rsync.gentoo.org/gentoo-portage/
auto-sync = yes

Aquí se define el mecanismo de sincronización. Cambiar sync-type a git es común si prefieres seguir el repositorio oficial en GitHub en vez de rsync.

Leer noticias del repositorio: tras sincronizar, Portage puede avisar de "news items" — mensajes críticos (cambios que rompen algo, migraciones necesarias).
root # eselect news list    # ver disponibles
root # eselect news read    # leer
root # eselect news purge   # marcar como leídos

5. Buscar paquetes

root # emerge --search firefox        # por nombre
root # emerge --searchdesc "web browser"  # también en descripción, más lento
Alternativa recomendada: app-portage/eix mantiene un índice propio y busca mucho más rápido que emerge --search. Vale la pena instalarlo temprano: emerge --ask app-portage/eix, y luego eix <paquete>.

6. Desinstalar y limpiar

Desinstalar un paquete específico riesgo medio 
root # emerge --ask --unmerge www-client/firefox

-C / --unmerge: elimina exactamente el paquete indicado, sin tocar sus dependencias huérfanas — esas se limpian aparte.

Limpiar paquetes obsoletos/huérfanos riesgo alto si no revisas antes 
# 1. Revisar SIEMPRE antes de ejecutar de verdad
root # emerge --ask --pretend --depclean

# 2. Si la lista se ve correcta, ejecutar
root # emerge --ask --depclean

--depclean elimina paquetes que ya no son necesarios: dependencias que quedaron huérfanas tras actualizaciones, o versiones antiguas de paquetes con slots múltiples (como el kernel).

Proteger un paquete de depclean: si Portage marca algo como huérfano pero lo usas manualmente fuera de @world, usa emerge --noreplace app-misc/foo para preservarlo sin agregarlo formalmente al conjunto mundial.

7. Conflictos de configuración: --autounmask

Cuando Portage no puede instalar algo con la configuración actual (falta un USE flag, requiere rama inestable, está enmascarado), no falla en silencio: te muestra exactamente qué cambio resolvería el conflicto.

Ejemplo: conflicto de USE flag 
root # emerge --ask media-video/mpv

# Salida típica de Portage:
# The following USE changes are necessary to proceed:
#  #required by mpv (argument)
# >=media-video/mpv-0.38.0 -vulkan
OpciónPara qué sirve
--autounmaskCalcula y propone el cambio necesario. Activo por defecto. No modifica archivos.
--autounmask-writeEscribe la propuesta directamente en /etc/portage/package.*/. No vuelve a intentar el emerge por sí solo.
--autounmask-keep-masksRestringe la propuesta a USE/keywords, sin proponer desenmascarar paquetes.
Flujo completo para aplicar el cambio 
root # emerge --ask --autounmask-write media-video/mpv
root # etc-update
root # emerge --ask media-video/mpv

# Proceso:
# 1. autounmask-write escribe el cambio propuesto (a veces como archivo ._cfg0000_*)
# 2. etc-update te muestra el diff y te deja aprobarlo o rechazarlo
# 3. Una vez aprobado, el archivo definitivo queda en package.use/ o package.accept_keywords/
# 4. Se reintenta el emerge, ahora sin conflicto

8. package.use/ y package.accept_keywords/

package.use/ — excepciones de USE flags por paquete

Directorio donde defines USE flags específicos de un paquete, sin tocar el USE= global de make.conf. No existen archivos por defecto — tú los creas.

Ejemplo: /etc/portage/package.use/mpv 
media-video/mpv -vulkan libplacebo

Sintaxis: categoría/paquete flag1 -flag2 flag3. Sin signo = activar; con - = desactivar. Puedes acotar por versión: >=media-video/mpv-0.38.0.

package.accept_keywords/ — permitir ramas inestables

Gentoo marca paquetes como estables (amd64) o inestables/testing (~amd64). Por defecto solo se instalan versiones estables. Si necesitas una versión más nueva que aún está en pruebas, la autorizas aquí — paquete por paquete, no globalmente.

Ejemplo: /etc/portage/package.accept_keywords/mpv riesgo medio 
media-video/mpv ~amd64

Esto autoriza instalar versiones ~amd64 (testing) solo de mpv, dejando el resto del sistema en la rama estable.

Para qué sirve separar en directorio: Portage lee todos los archivos dentro de package.use/ y package.accept_keywords/, sin importar el nombre. La convención de un archivo por paquete (o por tema) es solo para mantener orden y facilitar revertir cambios individuales.

9. Herramientas de inspección

equery (paquete gentoolkit) — consultar sin instalar 
root # emerge --ask app-portage/gentoolkit

root # equery list '*'                    # todo lo instalado
root # equery depends www-client/firefox  # qué depende de firefox
root # equery uses www-client/firefox     # USE flags activos/inactivos
root # equery files www-client/firefox    # archivos instalados por el paquete
root # equery belongs /usr/bin/firefox    # a qué paquete pertenece un archivo
revdep-rebuild — reparar enlaces rotos riesgo bajo 
root # revdep-rebuild

# Para qué sirve: tras actualizar librerías compartidas, algunos binarios
# pueden quedar enlazados contra versiones viejas. Este comando detecta
# esos casos y recompila los paquetes afectados.

10. Dependencias circulares

A veces el paquete A necesita a B para compilarse, y B necesita a A. Portage resuelve esto rompiendo el ciclo con una compilación en dos pasadas: instala una versión mínima de uno de los dos (a veces usando USE flags reducidos temporalmente), y luego reconstruye ambos ya con las dependencias completas satisfechas. Esto es automático — normalmente no necesitas intervenir, pero si ves mensajes de "circular dependencies" en un --pretend, es señal de que Portage ya está resolviendo esto internamente antes de compilar.

11. Nota sobre systemd

No aplica a tu instalación (OpenRC). Se incluye solo como referencia si en el futuro migras o comparas sistemas.

En un sistema con systemd como gestor de servicios, emerge funciona exactamente igual — la gestión de paquetes no cambia. Lo que cambia es cómo administras servicios:

TareaOpenRC (tu sistema)systemd
Habilitar servicio al arrancarrc-update add sshd defaultsystemctl enable sshd
Iniciar servicio ahorarc-service sshd startsystemctl start sshd
Ver estadorc-service sshd statussystemctl status sshd
Listar servicios habilitadosrc-update showsystemctl list-unit-files --state=enabled

Portage también expone el USE flag global systemd en make.conf para paquetes que ofrecen integración opcional (unidades .service, journal, etc.) — en tu configuración OpenRC ese flag debe permanecer desactivado.

12. Tabla resumen — dónde se configura

Archivo / directorioPropósito
/etc/portage/make.confUSE flags globales, opciones de compilación, mirrors, binhost. Se lee en cada emerge.
/etc/portage/package.use/USE flags específicos por paquete. Un archivo por paquete/tema (convención, no obligatorio).
/etc/portage/package.accept_keywords/Autoriza ramas inestables (~amd64) por paquete.
/etc/portage/package.mask / package.unmaskBloquea o desbloquea manualmente versiones específicas de paquetes.
/etc/portage/repos.conf/gentoo.confDefine cómo y desde dónde se sincroniza el árbol de ebuilds (emerge --sync).
/var/db/repos/gentooCopia local del árbol de ebuilds sincronizado.
