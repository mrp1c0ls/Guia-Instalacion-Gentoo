Capítulo 13 — Introducción a los dispositivos de bloque

El paso previo a particionar: cómo Linux nombra los discos y qué formatos de tabla de particiones existen.

13.1 · Dispositivos de bloque

Un dispositivo de bloque es la forma en que Linux representa un disco: una capa que permite leer y escribir en "bloques" de 4096 bytes sin importar la tecnología física (SATA, NVMe, USB, etc.). Cada tipo de conexión recibe un nombre distinto en /dev/.

Tipo de discoNombre en /dev/Notas
SATA, SAS, SCSI, USB/dev/sdaEl más común. 1ª partición: /dev/sda1
NVMe (SSD por PCIe)/dev/nvme0n1Más rápido. 1ª partición: /dev/nvme0n1p1
MMC / eMMC / SD/dev/mmcblk0No recomendado para el sistema base
VirtIO (VM / QEMU)/dev/vdaSolo en máquinas virtuales
💡
Para qué sirve saber estoTe permite reconocer de inmediato, con solo ver lsblk o fdisk -l, qué disco es cuál antes de tocar algo — clave para no particionar el disco equivocado.

13.2 · Tablas de particiones: GPT vs MBR

Un disco casi nunca se usa "en bruto"; se divide en particiones. La tabla de particiones es el índice que describe dónde empieza y termina cada una.

GPTMBR / DOS
AñoModerno1983 (legacy)
Límite de particionesPrácticamente ninguno4 primarias (o 3 + extendida)
Tamaño máx. de disco~8 ZiB2 TiB
Copia de respaldo de la tablaSí, al final del discoNo — un solo punto de falla
Requiere para UEFISí, casi obligatorioNo compatible
⚠️
Ojo con el dual-bootSi usas GPT en una PC configurada en modo BIOS (no UEFI), Windows se niega a arrancar desde ahí. Verifica el modo de tu firmware antes de elegir.

Recomendación del Handbook: usar GPT siempre que se pueda. MBR solo tiene sentido en hardware anterior a 2010 o algunos entornos de nube virtualizados.

13.3 · Almacenamiento avanzado

El medio de instalación también soporta, aunque no los cubre en detalle: Btrfs, ZFS, LVM y cifrado del disco raíz. Se mencionan como referencia para quien quiera ir más allá del esquema básico.

Herramientas: fdisk y parted

El capítulo solo las menciona; el uso real viene en el capítulo 15. fdisk funciona con MBR y GPT y es la que usa el Handbook. parted es una alternativa, más orientada a GPT desde el inicio.

Comandos internos de fdisk (modo interactivo)

TeclaAcciónRiesgo
pImprime la tabla de particiones actualbajo
nCrea una nueva particiónbajo (en memoria)
dMarca una partición para borrarmedio
tCambia el tipo de particiónbajo
gCrea tabla GPT nueva (borra todo)medio (reversible con q)
oCrea tabla MBR nueva (borra todo)medio (reversible con q)
iMuestra info de una partición: UUID, Type-UUIDbajo
wEscribe los cambios al disco de verdad y salealto — irreversible
qSale sin guardar nadabajo — botón de pánico
🛑
Nada se guarda hasta wTodo lo que haces con n, d, t, g u o vive solo en memoria. Si te equivocas, sal con q y el disco real queda intacto.
Ejemplo: crear el esquema GPT/UEFI paso a paso 
root # fdisk /dev/sda

Command (m for help): g          # tabla GPT nueva

Command (m for help): n          # partición ESP
Partition number (1-128, default 1): 1
First sector: [Enter]
Last sector: +1G

Command (m for help): t          # marcarla como EFI System
Partition number: 1
Type: 1

Command (m for help): n          # swap
...
Command (m for help): n          # root
...

Command (m for help): p          # revisar antes de guardar
Command (m for help): w          # ¡guardar y salir!

Ver UUIDs

Dentro de fdisk, la tecla i muestra el UUID de una partición individual (solo en GPT). Pero para ver todos los discos de un jalón, el Handbook usa blkid fuera de fdisk:

root # blkid
/dev/sda1: PARTUUID="c12a7328-f81f-11d2-ba4b-00a0c93ec93b"
/dev/sda2: PARTUUID="0657fd6d-a4ab-43c4-84e5-0933c84b4f4f"
/dev/sda3: PARTUUID="1cdf763a-5b4c-4dbf-99db-a056c504e8b2"
Tipo de identificador¿Qué identifica?¿Cuándo cambia?
PARTUUIDLa partición en síSolo si la recreas
UUID (filesystem)El contenido / sistema de archivosAl reformatear con mkfs
💡
Para qué sirve estoEstos identificadores son los que vas a usar más adelante en /etc/fstab en vez de /dev/sda1, porque no cambian aunque el orden de detección de discos cambie entre reinicios.
