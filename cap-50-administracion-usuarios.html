Capítulo 50 — Administración de usuarios

Gentoo Handbook AMD64 · Perfil: OpenRC · Sistema con systemd omitido salvo notas comparativas

Para qué sirve este capítulo: hasta ahora todo el trabajo se ha hecho como root, la cuenta con permisos totales sobre el sistema. Este capítulo crea una cuenta de usuario normal para el uso diario y define cómo recuperar permisos de root solo cuando se necesiten, en vez de tenerlos siempre activos.

50.1 — Crear un usuario para uso diario

Trabajar como root de forma permanente es riesgoso: un comando mal escrito (por ejemplo un rm -rf con la ruta equivocada) puede dañar el sistema completo, porque root no tiene restricciones. Un usuario normal solo puede afectar sus propios archivos y lo que sus grupos le permitan.

Grupos relevantes

GrupoPara qué sirve
wheelEl más importante: permite usar su para volverse root. Sin este grupo, el usuario no puede elevar privilegios con su.
usersGrupo genérico base para cuentas de usuario estándar.
audioAcceso a dispositivos de sonido.
videoAcceso a hardware de video y aceleración gráfica.
cdrom / usbAcceso directo a unidades ópticas o dispositivos USB.
cronPermite programar tareas con cron (ver Cap. 37).

Comando: crear el usuario

# Ejemplo con un usuario llamado "larry"
root # useradd -m -G users,wheel,audio -s /bin/bash larry
root # passwd larry
Ver opciones de useradd usadas y disponibles
FlagFunción
-mCrea la carpeta home (/home/larry) junto con el usuario. Sin esta opción, el usuario no tiene home.
-G grupo1,grupo2Agrega el usuario a grupos secundarios (separados por coma, sin espacios).
-s /bin/bashDefine la shell de login. Si se omite, puede quedar sin shell asignada o usar la que diga /etc/default/useradd.
-u UID(No usada arriba) Fuerza un UID específico en vez de que el sistema asigne el siguiente disponible.
-c "comentario"(No usada arriba) Campo GECOS: nombre completo u otra nota descriptiva.

Pasos que ejecuta el proceso

  1. useradd crea la entrada del usuario en /etc/passwd y su grupo primario en /etc/group.
  2. Con -m, copia el contenido de /etc/skel a la nueva carpeta /home/larry y ajusta los permisos.
  3. Con -G, añade al usuario como miembro secundario de cada grupo listado (edita /etc/group).
  4. passwd larry pide y confirma la contraseña, y la guarda cifrada en /etc/shadow.
Buena práctica: usar una contraseña distinta y no relacionada con la de root, de al menos 16 caracteres.

50.2 — Elevar privilegios temporalmente

Una vez que ya no se trabaja como root por defecto, se necesita una forma de recuperar esos permisos solo cuando haga falta. Hay tres caminos habituales:

Opción 1: su - (incluida de fábrica)

user $ su -
Password: # contraseña de root

Para qué sirve: abre una sesión completa como root (con el - además carga el entorno de root, como su $PATH y variables). Requiere conocer la contraseña de root. Es simple, pero todo o nada: no hay forma de limitar qué comandos se pueden correr.

Opción 2: sudo app-admin/sudo

Para qué sirve: ejecuta un comando puntual como root (u otro usuario) sin abrir una sesión aparte, pidiendo la contraseña del propio usuario (no la de root). Permite definir con precisión qué usuarios pueden ejecutar qué comandos.

# Instalación
root # emerge --ask app-admin/sudo

# Uso básico
user $ sudo comando

# Editar la configuración de forma segura (valida sintaxis antes de guardar)
root # visudo
Ver configuración y opciones comunes de sudo
ElementoDescripción
/etc/sudoersArchivo principal de reglas. Se edita solo con visudo para evitar dejarlo con errores de sintaxis que bloqueen el acceso.
%wheel ALL=(ALL) ALLRegla típica: cualquier miembro del grupo wheel puede ejecutar cualquier comando como cualquier usuario.
usuario ALL=(ALL) NOPASSWD: ALLPermite a ese usuario usar sudo sin pedir contraseña (usar con cuidado).
sudo -iAbre una sesión interactiva como root, similar a su -.
sudo -u usuario comandoEjecuta el comando como otro usuario, no necesariamente root.
/etc/sudoers.d/Directorio para agregar reglas en archivos separados sin tocar el archivo principal.

Opción 3: doas app-admin/doas

Para qué sirve: alternativa minimalista a sudo, con muchas menos opciones de configuración (menor superficie de ataque) y sintaxis más simple. Buena opción para sistemas de un solo usuario.

# Instalación
root # emerge --ask app-admin/doas

# Configuración: crear el archivo (no existe por defecto)
root # nano -w /etc/doas.conf
# Ejemplo de regla en /etc/doas.conf: permite a "larry" usar doas
# pidiendo su propia contraseña
permit persist larry as root
persist evita que se pida contraseña en cada comando durante unos minutos, igual que hace sudo por defecto.

Comparativa rápida

MétodoContraseña que pideConfiguraciónGranularidad
su -La de rootNinguna (viene listo)Ninguna: todo o nada
sudoLa del usuario/etc/sudoers vía visudoAlta: por comando, usuario, grupo, host
doasLa del usuario/etc/doas.confMedia: reglas simples
Nota systemd: en sistemas con systemd como gestor de servicios existe además run0, integrado en systemd, que cumple un rol similar a sudo sin necesidad de instalar un paquete aparte. No aplica en esta instalación (perfil OpenRC).

50.3 — Deshabilitar el login de root RIESGO MEDIO

Advertencia del handbook: antes de deshabilitar el login de root, hay que confirmar que el usuario normal ya está en el grupo wheel y que su, sudo o doas funcionan correctamente. De lo contrario, el sistema queda sin forma de administrarse y se necesita un rescate desde el medio de instalación.

Comando: bloquear el login de root

root # passwd -l root

Para qué sirve: antepone un carácter inválido al hash de la contraseña en /etc/shadow, de forma que ningún login por contraseña puede tener éxito. La cuenta root sigue existiendo y sigue siendo accesible vía su desde una sesión ya elevada, o revirtiendo el bloqueo.

Alternativa: eliminar la contraseña por completo

root # passwd -d root

Para qué sirve: borra el hash de la contraseña de root en vez de invalidarlo. El resultado práctico es similar (no se puede iniciar sesión por contraseña), pero es un estado distinto a nivel de archivo: -l es reversible con passwd -u root; con -d hay que asignar una contraseña nueva desde cero.

Ver otras opciones útiles de passwd
FlagFunción
-lBloquea (lock) la cuenta, invalidando el hash actual.
-uDesbloquea una cuenta previamente bloqueada con -l.
-dElimina la contraseña de la cuenta.
-eFuerza que la contraseña expire, obligando a cambiarla en el próximo login.
-SMuestra el estado de la cuenta (bloqueada, con contraseña, etc.) sin modificar nada.
