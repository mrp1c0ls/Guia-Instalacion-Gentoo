43. Selección del bootloader

¿Para qué sirve? El bootloader es lo primero que se ejecuta tras el firmware (UEFI/BIOS). Sin él, el kernel de Linux nunca se carga en memoria — el equipo se queda "mirando" el firmware sin saber a dónde ir.

Este capítulo no tiene comandos: es la bifurcación de decisión antes de instalar. El manual documenta 3 rutas para UEFI (tu caso) y 1 para BIOS legado.

Vocabulario clave: emerge vs install

TérminoQué haceRiesgo
emergeCompila/descarga el paquete del bootloader vía Portage. Solo lo deja disponible en el sistema.Bajo reversible
installEl bootloader escribe físicamente en el disco o en la partición EFI, quedando activo para el próximo arranque.Alto paso crítico

Comparativa de opciones (UEFI)

GRUB Default

Más maduro, mayor compatibilidad (BIOS + UEFI), detecta otros SO (dual boot con os-prober).

Más pesado y con más piezas móviles.

systemd-boot

Chainloader ligero. Funciona con OpenRC o systemd. Buen soporte de Secure Boot.

Requiere kernel-install de systemd — kernels van a /efi, no a /boot.

EFI Stub

El kernel se arranca directo desde el firmware, sin bootloader intermedio.

Minimalista pero rígido; no garantizado en todo firmware UEFI.

Analogía NixOS: en NixOS nixos-rebuild switch reconfigura el bootloader automáticamente a partir de configuration.nix. En Gentoo separas manualmente: 1) emerge el paquete, 2) ejecutas el comando de install al disco, 3) generas el archivo de configuración. Mismo concepto, sin la capa declarativa.

🔧 Dónde se configura todo: sys-kernel/installkernel

Esto es clave: el paquete installkernel es el "pegamento" entre instalar un kernel nuevo y que tu bootloader elegido se entere de que existe. Su comportamiento cambia según qué USE flags actives — ahí es donde realmente "seleccionas" el bootloader, no solo al emerger GRUB/systemd-boot por separado.
BootloaderUSE flags en installkernelDónde va el kernel
GRUBgrub (auto-corre grub-mkconfig)/boot
systemd-bootsystemd systemd-boot/efi
EFI Stubefistub/efi
Ejemplo para tu setup (GRUB + OpenRC, ya configurado según tus notas previas)
sys-kernel/installkernel grub dracut
💡 Esta es la razón por la que ya tenías grub dracut escrito en /etc/portage/package.use/ desde antes de llegar a este capítulo: ese flag es el que hace que, cada vez que instales un kernel nuevo, grub-mkconfig se ejecute automáticamente.
