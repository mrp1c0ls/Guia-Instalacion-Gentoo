Capítulo 26 Opcional: Usar systemd como sistema y gestor de servicios

En una frase: este capítulo no da comandos — es un aviso de que, desde aquí, el manual mostrará dos caminos (OpenRC y systemd) cada vez que un paso sea diferente entre ambos.

¿Qué está pasando aquí? Sin comandos

Hasta este punto de la instalación (crear particiones, extraer el stage3, entrar al chroot, configurar Portage) el proceso es idéntico sin importar qué "init system" vayas a usar. A partir de este capítulo eso cambia: zona horaria, red, logging, cron, servicios de arranque, etc. tienen comandos distintos según el sistema elegido.

Es simplemente el punto donde el manual "bifurca" el camino. No hay que instalar ni ejecutar nada en este capítulo.

¿Qué es un "init system"?

Es el primer proceso que arranca el kernel de Linux (PID 1) y el encargado de levantar todos los demás servicios (red, logs, sshd, etc.) en el orden correcto. Es una pieza fundamental del sistema operativo.

Para qué sirve saber esto: como ya elegiste OpenRC desde el Capítulo 3, este capítulo confirma que debes seguir la rama "OpenRC" cada vez que el manual presente dos columnas o dos bloques de comandos.

¿Por qué OpenRC para este proyecto? Contexto

  • Es la opción tradicional de Gentoo, con más documentación específica de la distro.
  • Los scripts son shell puro, ideales para aprender qué hace cada servicio internamente (encaja con tu enfoque de estudiar cada paso).
  • Menos "piezas" moviéndose por debajo del sistema — más fácil de depurar cuando algo falla.
¿Y si más adelante quiero cambiar a systemd?

Es posible, pero implica reinstalar varios componentes base (stage3 distinto, perfil de Portage distinto, y volver a configurar red, logging y servicios con las herramientas de systemd). No es un simple "cambio de interruptor" — el manual lo trata como una decisión que se toma antes de llegar a este punto, no después.
