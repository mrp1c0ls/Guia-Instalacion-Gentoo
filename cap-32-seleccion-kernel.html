Capítulo 32 — Selección del Kernel

Distribution Kernel · gentoo-sources · USE flags · modprobed-db

El kernel es la capa entre el hardware y todos los programas del sistema. Este capítulo decide cómo se va a construir y mantener a lo largo del tiempo — es una de las decisiones con más impacto a futuro en tu instalación.

32.0 El dilema central

Hay dos caminos. Ambos son válidos y reversibles (se puede cambiar de uno a otro después), pero implican filosofías distintas de mantenimiento:

Distribution Kernel

  • Portage configura, compila e instala todo
  • Se actualiza junto con @world
  • Recomendado para empezar
  • Mínima intervención manual

Configuración manual

  • Vos elegís cada opción del kernel
  • Usa sys-kernel/gentoo-sources
  • Control total, más trabajo
  • Hay que repetir el proceso en cada actualización
Dato importante: un kernel compilado a mano no usa menos RAM que uno de distribución. El kernel de Linux es modular — en ambos casos solo se carga lo que el hardware realmente necesita. La diferencia real está en cuánto control querés tener, no en el rendimiento.

32.1 Distribution Kernel

Es el camino recomendado para la mayoría de las instalaciones. Portage trata al kernel como un paquete más: lo configura con una selección genérica de opciones que cubre casi todo el hardware existente, lo compila (o lo descarga ya compilado) y lo instala.

Opción A — Compilar desde fuente

Compila localmente · tarda más
Comando
root # emerge --ask sys-kernel/gentoo-kernel

Descarga el código fuente del kernel (con los parches propios de Gentoo aplicados) y lo compila en tu propia máquina, usando las USE flags y opciones de make.conf que ya definiste. El resultado es un kernel "a tu medida" dentro del margen que permite la configuración genérica de distribución.

Para qué sirve: si tu CPU o hardware es poco común, o si querés que tus USE flags globales (como flags de arquitectura, firmware específico, etc.) influyan en el resultado, esta es la opción. El costo es tiempo: compilar un kernel completo puede tardar bastante según el hardware.

Opción B — Binario precompilado

Solo descarga · instalación rápida
Comando
root # emerge --ask sys-kernel/gentoo-kernel-bin

En vez de compilar, Portage descarga un kernel ya compilado por el proyecto Gentoo, con una configuración genérica pensada para funcionar en la mayoría del hardware "de fábrica". No consume tiempo de CPU en compilación — es prácticamente instantáneo comparado con la opción A.

Para qué sirve: ideal si priorizás rapidez de instalación, estás en una máquina virtual, un laptop con hardware común, o simplemente no querés esperar una compilación. La contrapartida es menos margen de personalización, porque no pasa por tu make.conf de la misma forma.

Ambas opciones son intercambiables en cuanto a mantenimiento: las dos se actualizan igual, vía emerge -avuDN @world, y ambas requieren que installkernel esté configurado con un generador de initramfs (por ejemplo, Dracut) antes de instalarlas.

32.1.a El USE flag dist-kernel

USE flag
📍 Se configura en /etc/portage/make.conf
/etc/portage/make.conf
USE="dist-kernel"

Es un interruptor global que le dice a Portage: "cuando actualices el kernel, hacé también el trabajo de limpieza asociado, sin que yo tenga que acordarme."

Sin este flag, después de cada actualización del kernel tendrías que correr manualmente:

root # emerge --ask @module-rebuild

para reconstruir módulos externos (como drivers de NVIDIA o ZFS, que dependen de la versión exacta del kernel) y regenerar el initramfs. Con dist-kernel activo, todo eso pasa automáticamente cuando el kernel sube de versión.

Analogía NixOS: es similar a lo que hace nixos-rebuild switch al regenerar el initrd y actualizar el bootloader en cada nueva generación — automático, sin pasos manuales sueltos. dist-kernel le da ese mismo comportamiento a Gentoo, que por defecto es más manual.

32.1.b Mantenimiento y limpieza

Actualizar todo el sistema (incluido el kernel si hay versión nueva)
root # emerge --sync
root # emerge -avuDN @world
Para qué sirve: --sync baja la lista más reciente de paquetes disponibles (no instala nada todavía). -avuDN @world sí actualiza lo instalado. El flag -a (ask) muestra qué va a cambiar antes de confirmar.
Limpiar kernels viejos
root # emerge --depclean
# o, específicamente:
root # emerge --prune sys-kernel/gentoo-kernel sys-kernel/gentoo-kernel-bin
Para qué sirve: libera espacio en disco eliminando versiones antiguas que Portage conserva hasta que se le pide limpiar.

32.2 Configuración manual (alternativa)

Usa sys-kernel/gentoo-sources en vez de un kernel de distribución. Acá vos configurás cada opción a mano con herramientas como make menuconfig. Hay tres formas de decidir qué incluir:

Opción 1 — Modprobed-db (automatiza la detección con el tiempo)

sys-kernel/modprobed-db es un demonio que corre en segundo plano (vía cron o un timer de systemd) y va registrando qué módulos del kernel usa tu sistema a lo largo del tiempo — no solo en el momento de instalar, sino con cada dispositivo nuevo que conectás.

Ejemplo: si semanas después de instalar Gentoo conectás un control de Xbox, modprobed-db anota ese módulo, y la próxima vez que reconstruyas el kernel, ese soporte ya está incluido automáticamente — sin que vos tengas que acordarte de agregarlo.

root # emerge --ask sys-kernel/modprobed-db
Para qué sirve: pensado para quien compila el kernel manualmente pero no quiere estar adivinando qué módulos incluir cada vez. Es la opción más "hands-off" dentro del camino manual — se usa normalmente junto con gentoo-kernel-bin como base.
Opción 2 — Proceso asistido (detección puntual, una sola vez)

A diferencia de modprobed-db (que observa con el tiempo), este método hace una detección instantánea del hardware presente en el momento de la instalación, usando dos herramientas:

  • lspci — lista los dispositivos conectados por PCI (tarjeta de red, gráfica, etc.)
  • lsmod — muestra qué módulos ya está usando el medio de instalación (el "live CD"), lo cual da pistas de qué necesitás activar
root # emerge --ask sys-apps/pciutils
root # cd /usr/src/linux
root # make localmodconfig
Para qué sirve: make localmodconfig autodetecta los módulos que el sistema está usando ahora mismo y genera una configuración base con eso. Es un punto de partida razonable si no querés empezar de cero, pero no seguirá aprendiendo después como modprobed-db.

Después de esto, se puede revisar manualmente con una interfaz de texto:

root # make nconfig
Para qué sirve: abre un menú interactivo para ajustar opciones específicas del kernel a mano, por si la autodetección se saltó algo.
Opción 3 — Configuración manual completa

Sin ayuda de detección automática: se configura cada opción del kernel a mano, una por una. Requiere conocer bien el hardware propio (controladores de disco, tarjeta de red, sistema de archivos, etc.). Es la opción de máximo control, pero también la de mayor curva de aprendizaje y riesgo de olvidar algo esencial (como el driver del disco donde arranca el sistema).

32.2.4 Compilar e instalar (camino manual)

Toma tiempo · no interrumpir
Comandos
root # make -j$(nproc) && make modules_install
root # make install
ComandoPara qué sirve
make -j$(nproc)Compila el kernel usando todos los núcleos de CPU disponibles en paralelo (nproc los cuenta automáticamente), acelerando la compilación
make modules_installInstala los módulos ya compilados en /lib/modules/
make installCopia la imagen del kernel a /boot/. Si installkernel está presente, delega en él para nombrar el archivo con su versión y, opcionalmente, generar initramfs y actualizar el bootloader
