Capítulo 8 · Preparando los discos

Sistemas de archivos, activación de swap, y particionado GPT/UEFI vs MBR/BIOS

Ya tienes el espacio dividido en particiones (visto en el capítulo 2). Ahora toca dos cosas: darle formato a cada partición con un sistema de archivos, y activar la swap. También cubrimos aquí, como referencia, cómo se ve el particionado completo tanto en GPT/UEFI como en el esquema clásico MBR/BIOS, y una alternativa a fdisk: cfdisk.

🎯 Para qué sirve este capítulo: sin sistema de archivos, una partición es solo espacio vacío e inutilizable. Este paso convierte esas particiones en lugares donde Linux realmente puede guardar archivos.

1. ¿Qué es un sistema de archivos?

Es la forma en que el sistema organiza y guarda los datos dentro de una partición: cómo nombra archivos, cómo controla permisos, cómo sabe qué bloques del disco pertenecen a cada archivo. Crear la partición (con fdisk o cfdisk) es como delimitar un terreno; formatearla con mkfs es como construir los cimientos y las calles adentro.

2. Particionado GPT + UEFI (tu configuración)

Riesgo medio — modifica la tabla de particiones
ParticiónPunto de montajeSistemaDescripción
/dev/sda1/efivfatEFI System Partition (ESP)
/dev/sda2—swapPartición swap
/dev/sda3/xfsPartición raíz

Formatear con mkfs

# ESP: siempre FAT32, obligatorio para que el firmware UEFI encuentre el bootloader
root # mkfs.vfat -F 32 /dev/sda1

# Raíz con XFS (recomendado)
root # mkfs.xfs /dev/sda3
🎯 Para qué sirve la ESP: es la partición donde UEFI busca el gestor de arranque (GRUB). Si no está en FAT32, el firmware simplemente no la reconoce y el sistema no arranca.
¿Necesito una BIOS boot partition en modo UEFI?

No. La BIOS boot partition (1-2 MB) solo es necesaria cuando el disco tiene tabla GPT pero el sistema arranca en modo legacy BIOS (mezcla poco común). En UEFI puro, o en MBR clásico, no se usa.

3. Particionado MBR + BIOS legacy (referencia)

Riesgo medio — modifica la tabla de particiones

Si el equipo es anterior a ~2010 o se necesita compatibilidad legacy, este es el esquema equivalente usando MBR/DOS en vez de GPT.

ParticiónPunto de montajeSistemaDescripción
/dev/sda1/bootxfsPartición de arranque (marcada * booteable)
/dev/sda2—swapPartición swap
/dev/sda3/xfsPartición raíz

Creación con fdisk (resumen)

root # fdisk /dev/sda
# crear tabla MBR nueva (borra todo lo existente)
Command (m for help): o
# nueva partición primaria /boot de 1G, marcada booteable con 'a'
Command (m for help): n
Command (m for help): a
# nueva partición swap de 4G, tipo 82
Command (m for help): n
Command (m for help): t
# partición raíz con el resto del espacio
Command (m for help): n
# guardar cambios
Command (m for help): w

Formatear (MBR/BIOS)

# /boot con cualquier sistema soportado por GRUB, XFS en este ejemplo
root # mkfs.xfs /dev/sda1

# raíz
root # mkfs.xfs /dev/sda3
Diferencia clave: en GPT/UEFI el bootloader vive en una partición FAT32 (/efi) que el firmware lee directamente. En MBR/BIOS, GRUB se instala en el sector de arranque del disco mismo, y /boot solo guarda el kernel y los archivos de configuración — por eso no necesita ser FAT32.

4. Alternativa a fdisk: cfdisk

Riesgo medio

cfdisk hace lo mismo que fdisk (crear/borrar/formatear particiones) pero con una interfaz visual de menús, en vez de comandos de una letra. Es más amigable para quien recién empieza.

🎯 Para qué sirve: reduce el riesgo de errores al escribir el comando equivocado, porque todas las acciones se seleccionan con las flechas del teclado y se confirman explícitamente.
root # cfdisk /dev/sda

Dentro de cfdisk, navega con las flechas ↑ ↓ y selecciona acciones con Enter:

  • [New] — crea una partición nueva en el espacio libre (pide el tamaño, ej. 1G)
  • [Type] — cambia el tipo de partición (ej. "EFI System" o "Linux swap")
  • [Bootable] — marca la partición como booteable (solo en MBR)
  • [Delete] — elimina la partición seleccionada
  • [Write] — guarda los cambios al disco (pide confirmar escribiendo yes)
  • [Quit] — sale sin guardar si aún no se ha escrito
fdisk vs cfdisk — ¿cuál usar?
fdiskcfdisk
InterfazComandos de una letra (n, d, w...)Menús visuales con flechas

Ambos producen el mismo resultado final. El Handbook usa fdisk por defecto, pero cfdisk es perfectamente válido si te sientes más cómodo viendo la tabla de particiones de forma gráfica.

5. Activar la partición swap

Riesgo bajo — reversible

El swap no se "formatea" con mkfs; se inicializa con mkswap y luego se activa con swapon.

root # mkswap /dev/sda2
root # swapon /dev/sda2
🎯 Para qué sirve el swap: es espacio en disco que el kernel usa como "memoria RAM extra" cuando la RAM real se satura, moviendo ahí páginas de memoria poco usadas. Es más lento que la RAM, pero evita que el sistema se quede sin memoria.

6. ¿Qué son los inodos? (concepto clave)

Un inodo es la estructura donde el sistema de archivos guarda toda la información de un archivo excepto su nombre y contenido: dueño, permisos, fechas, y en qué bloques del disco están sus datos.

  • El contenido del archivo son los datos reales en el disco.
  • El inodo es la "ficha" con los metadatos del archivo.
  • El nombre del archivo solo apunta a ese inodo.
Por qué importa: cada sistema de archivos tiene un número limitado de inodos, fijado al crearlo. Si se agotan (típico con muchísimos archivos pequeños), no se pueden crear archivos nuevos aunque sobre espacio en disco.

Particiones ext4 pequeñas

# reserva más inodos de lo normal — útil en particiones menores a 8 GiB
root # mkfs.ext4 -T small /dev/<dispositivo>
