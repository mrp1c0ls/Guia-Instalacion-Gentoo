Capítulo 7 — Configuración automática de la red

Handbook de Gentoo AMD64 · Instalación · Networking (parte 1)
En una frase: antes de instalar nada hace falta internet en el sistema live. Este capítulo revisa si la red ya funciona sola (lo más común) y cómo comprobarlo.

¿Por qué existe este paso?

Todo lo que sigue en la instalación (descargar el stage3, sincronizar Portage, compilar el kernel) necesita salir a internet. Antes de tocar cualquier configuración manual, el Handbook te pide comprobar si ya tienes conexión, porque en la mayoría de los casos no hay que configurar nada.

"A lo mejor ya funciona" Concepto

Si tu equipo está conectado por cable Ethernet a un router con DHCP —el caso típico en casa o en la oficina— es muy probable que la red ya haya quedado configurada sola al arrancar el medio de instalación.

Para qué sirve saber esto: te ahorra tiempo. Si tienes cable y router normal, salta directo a la sección de "Comprobar la conexión" antes de intentar configurar nada a mano.

DHCP Concepto

DHCP (Dynamic Host Configuration Protocol) es el protocolo que le entrega automáticamente a tu equipo todo lo que necesita para hablar en la red: dirección IP, máscara de red, ruta por defecto, servidores DNS, etc.

Para que funcione tiene que existir un servidor DHCP en la misma red local — normalmente es el propio router. Por defecto, el medio live de Gentoo usa NetworkManager, que intenta conectarse por DHCP automáticamente. Si eso no pasa, lo primero es revisar el cable físico.

Comprobar la conexión (Testing the network)

Tres chequeos, de lo más básico a lo más específico:

1. ¿Hay una ruta por defecto? Bajo riesgo 
root # ip route
default via 192.168.0.1 dev enp1s0
Para qué sirve: la ruta por defecto es la "puerta de salida" hacia internet. Si el comando no muestra ninguna línea que empiece con default, no hay salida a internet configurada — ese es el problema a resolver primero.
2. ¿Hay conectividad básica? Bajo riesgo 
root # ping -c 3 1.1.1.1
Para qué sirve: confirma que hay salida real a internet. Se usa una IP directa (no un nombre de dominio) a propósito, para descartar de entrada cualquier problema de DNS y enfocarse solo en si hay conexión física/lógica.
3. ¿Funciona DNS + HTTPS? Bajo riesgo 
root # curl --location gentoo.org --output /dev/null
Para qué sirve: prueba en un solo paso que el nombre de dominio se resuelve (DNS) y que se puede descargar por HTTPS, que es justo lo que necesitará Portage más adelante.

Cómo interpretar los resultados

  • Todo funciona → continuar directo con la preparación de discos.
  • ping funciona pero curl falla → el problema es de DNS (se resuelve configurando /etc/resolv.conf, visto en un capítulo posterior).
  • Nada funciona → hay que revisar la información de las interfaces de red, probar con nmtui, o configurar la red manualmente (próximos capítulos).

Para enriquecer: ¿por qué probar con IP antes que con dominio?

Es una técnica útil fuera de la instalación también: separar capas del problema. Si el ping a una IP falla, el problema está en la capa de red (cable, router, DHCP). Si el ping a la IP funciona pero curl a un dominio falla, el problema está aislado a DNS. Este tipo de diagnóstico por capas se aplica en casi cualquier troubleshooting de red, no solo en Gentoo.
