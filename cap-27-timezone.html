Zona horaria (Timezone)

Cómo decirle al sistema en qué parte del mundo está — un paso corto pero necesario
⚠️ Este paso no aplica si tu sistema usa musl libc en vez de glibc. Si no sabes qué es eso, probablemente usas glibc y este capítulo sí te aplica.

¿Qué estamos haciendo aquí?

Linux necesita saber en qué zona horaria vive tu equipo para mostrar la hora local correcta (aunque internamente el reloj del sistema siga funcionando en UTC). Gentoo trae precargada una base de datos con todas las zonas horarias del mundo, guardada en /usr/share/zoneinfo/. Tu trabajo es simplemente decirle al sistema cuál de esas usar.

¿Para qué sirve esto? El sistema siempre consulta un solo archivo — /etc/localtime — para saber la hora local. En vez de copiar un archivo pesado ahí, se crea un enlace simbólico (como un acceso directo) que apunta a la zona horaria que elijas. Cambiar de zona horaria en el futuro es tan simple como rehacer ese enlace.

Paso 1 — Ver las zonas disponibles Riesgo bajo

Listar continentes/regiones
root # ls -l /usr/share/zoneinfo
Listar ciudades dentro de una región (ejemplo: América)
root # ls -l /usr/share/zoneinfo/America/
Para qué sirve: solo estás mirando, no cambias nada todavía. Sirve para confirmar el nombre exacto del archivo que necesitas (mayúsculas, guiones bajos, etc.) antes de crear el enlace.

Paso 2 — Crear el enlace simbólico Riesgo medio

Ejemplo con Bruselas (tú usarías tu propia zona)
root # ln -sf ../usr/share/zoneinfo/Europe/Brussels /etc/localtime
Para qué sirve: este comando es el que realmente configura la zona horaria. -s crea un enlace simbólico (no copia el archivo), y -f fuerza la sobreescritura si ya existía un enlace ahí. A partir de este momento, cada vez que el sistema pida la hora, seguirá este enlace hasta la zona elegida.
¿Por qué la ruta empieza con ../?

El enlace se va a crear dentro de /etc/. Cuando usas una ruta relativa como ../usr/share/zoneinfo/..., esa ruta se interpreta desde la ubicación del enlace (o sea, desde /etc/), no desde tu directorio actual de trabajo. Por eso el ../ "sube" un nivel desde /etc/ hasta la raíz /, y de ahí baja a /usr/share/zoneinfo/....

¿Por qué no usar una ruta absoluta como /usr/share/zoneinfo/... directamente? También funciona, pero una ruta relativa es más portátil: sigue funcionando incluso si el sistema se monta bajo una raíz alterna (por ejemplo, si estás reparando el sistema desde un live USB y montas todo en /mnt/gentoo).

Cuidado con las zonas Etc/GMT*: sus nombres están invertidos por una rareza histórica del estándar POSIX. Etc/GMT-8 en realidad significa GMT+8, no GMT-8. Mejor evítalas por completo y usa siempre una zona geográfica real (ciudad/región), como America/Monterrey o America/Mexico_City.

Zonas horarias relevantes para México (Tamaulipas)

Zona horariaAplica a
America/MatamorosTamaulipas (sigue horario de EE. UU./frontera, DST incluido)
America/MonterreyZona centro de México (Nuevo León y la mayoría del país)
America/Mexico_CityZona centro general (alias más reconocido)

Tamaulipas tiene una particularidad: algunos municipios fronterizos usan el horario de la frontera (que sí observa horario de verano/DST), por eso existe la entrada específica America/Matamoros. Verifica cuál corresponde a tu municipio antes de crear el enlace.

Paso 3 — Verificar (opcional pero recomendado)

Confirmar que el enlace apunta a donde debe
root # ls -l /etc/localtime
Para qué sirve: te muestra hacia dónde apunta el enlace ahora mismo, así confirmas que quedó bien antes de seguir adelante.
¿Y si uso systemd en vez de OpenRC?

Con systemd existe la herramienta timedatectl, que hace lo mismo pero de forma más guiada: 

root # timedatectl list-timezones
root # timedatectl set-timezone America/Monterrey

Internamente crea el mismo tipo de enlace simbólico relativo en /etc/localtime, solo que valida el nombre por ti y evita que te equivoques al escribir la ruta a mano.

Nota: en tu instalación estás usando OpenRC, así que el método manual con ln -sf es el que te corresponde.

💡 En este capítulo no hay mucho paralelismo útil con NixOS más allá de que, ahí, la zona horaria se declara como una línea de texto en configuration.nix (time.timeZone = "...") y el sistema genera el enlace por ti al aplicar la configuración. Aquí en Gentoo, tú creas ese enlace manualmente — mismo resultado, un paso más explícito.

Resumen rápido

1) Busca tu zona en /usr/share/zoneinfo/ → 2) crea el enlace con ln -sf ../usr/share/zoneinfo/TU_ZONA /etc/localtime → 3) evita las zonas Etc/GMT* → 4) verifica con ls -l /etc/localtime. Listo, siguiente capítulo: configuración de locales.
