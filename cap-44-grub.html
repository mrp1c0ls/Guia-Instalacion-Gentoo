Capítulo 44 · Bootloader — GRUB y alternativas

Instalación de Gentoo · Configuración: GPT + UEFI · dracut · OpenRC

¿Para qué sirve este capítulo?

El bootloader es el primer programa que corre después del firmware (UEFI). Su único trabajo es encontrar el kernel de Linux, cargarlo en memoria y arrancarlo con los parámetros correctos. Sin bootloader, el firmware enciende pero no sabe qué sistema operativo cargar.

Dos verbos distintos
Emerge = descargar/compilar el paquete con Portage (reversible, sin riesgo).
Install = escribir el bootloader físicamente en el disco o en la partición EFI (ESP) — esto es lo que lo activa para el próximo arranque.

Flujo de arranque con GRUB en tu configuración (GPT + UEFI + dracut).

44.1 — Emerge (instalar el paquete GRUB)

Para qué sirve: descargar y compilar GRUB con las opciones necesarias para tu firmware (UEFI en tu caso).

📍 Se configura en: /etc/portage/make.conf
Habilitar soporte UEFI antes de compilarRIESGO BAJO 
echo 'GRUB_PLATFORMS="efi-64"' >> /etc/portage/make.conf
emerge --ask sys-boot/grub
Opciones de GRUB_PLATFORMS
No solo existe efi-64. GRUB soporta múltiples plataformas de arranque en la misma variable (separadas por espacio): pc (BIOS legacy), efi-32, efi-64, coreboot, ieee1275 (Open Firmware/PowerPC), entre otras. Solo necesitas la que corresponda a tu firmware real.

Si ya compilaste GRUB sin esa variable, se recompila así:

Recompilar con nuevas USE/variablesRIESGO BAJO 
emerge --ask --update --newuse --verbose sys-boot/grub

44.2 — Install (grabar GRUB en el disco/ESP)

Para qué sirve: copiar los archivos ejecutables de GRUB a la partición donde el firmware los va a buscar al encender la máquina.

Punto de no retorno
Este es el paso más delicado de toda la instalación. Si la partición ESP (/efi) no está montada al ejecutar el comando, GRUB puede instalarse en la carpeta equivocada sin mostrar ningún error, dejando el sistema sin forma de arrancar.

44.2.1 — Legacy BIOS (no aplica a tu setup)

📍 Se ejecuta en: chroot, con el disco completo como destino
Instalar en el MBR del discoRIESGO ALTO 
grub-install /dev/sda

Se instala en el disco entero (no en una partición), porque BIOS legacy no usa un sistema de archivos para el bootloader.

44.2.2 — UEFI (tu caso)

📍 Requiere: /efi ya montada
Instalar en la partición EFIRIESGO ALTO 
grub-install --efi-directory=/efi

Copia los archivos (como grubx64.efi) dentro de /efi/EFI/Gentoo/. El firmware UEFI guarda una entrada de arranque apuntando a esa ruta.

Firmware UEFI "raro" que solo busca /EFI/BOOT/

Algunas placas madre con implementaciones UEFI defectuosas ignoran las entradas de arranque registradas y solo cargan el archivo ubicado en la ruta genérica /EFI/BOOT/BOOTX64.EFI. Para ese caso, se usa la opción --removable, que fuerza a GRUB a instalarse también ahí:

Instalación en modo "removable"RIESGO MEDIO 
grub-install --target=x86_64-efi --efi-directory=/efi --removable
Secure Boot (opcional, no lo necesitas por defecto)

Para qué sirve: permitir que el sistema arranque con Secure Boot activo en el firmware, verificando que el bootloader y el kernel estén firmados con una llave de confianza.

El mecanismo usa shim, un pequeño pre-cargador ya firmado por Microsoft y aceptado por la mayoría de los firmwares UEFI por defecto. El flujo general:

  1. Convertir el certificado de tu llave de firma a formato DER
  2. Importarlo a la lista de confianza de shim (pide una contraseña temporal)
  3. Registrar shim ante el firmware UEFI como entrada de arranque
Convertir certificadoRIESGO BAJO 
openssl x509 -in /path/to/kernel_key.pem -inform PEM -out /path/to/kernel_key.der -outform DER
Importar a MOKlist de shimRIESGO BAJO 
mokutil --import /path/to/kernel_key.der
Registrar shim en el firmwareRIESGO MEDIO 
efibootmgr --create --disk /dev/boot-disk --part boot-partition-id \
  --loader '\EFI\Gentoo\shimx64.efi' --label 'GRUB via Shim' --unicode
Nota
El proceso no termina hasta reiniciar: al arrancar, shim mostrará MokManager pidiendo la contraseña definida en el paso de importación. Ahí se confirma la llave y recién entonces el firmware confía en tu GRUB firmado.
Depurar errores de grub-install

Si aparece el mensaje "EFI variables are not supported on this system", casi siempre significa que el medio live se arrancó en modo Legacy/BIOS en vez de UEFI. La solución habitual es repetir la instalación con --removable (ver arriba), ya que sobrescribe la ruta genérica que el firmware sí reconoce en modo legacy accidental.

44.3 — Configure (generar grub.cfg)

Para qué sirve: generar el archivo real que GRUB lee al arrancar: qué kernel cargar, qué initramfs usar, y con qué parámetros.

📍 Se configura en: /etc/default/grub (opciones) · Se genera en: /boot/grub/grub.cfg
Generar la configuración finalRIESGO BAJO 
grub-mkconfig -o /boot/grub/grub.cfg

GRUB escanea /boot/ automáticamente y detecta:

  • El kernel más reciente disponible (vmlinuz-...)
  • La imagen initramfs correspondiente — en tu caso, la que genera dracut
Verificación obligatoria
La salida del comando debe mostrar al menos un Found linux image y, por usar dracut, también un Found initrd image. Si falta alguno, revisa /boot/ con ls — probablemente algo falló antes en la instalación del kernel.

Personalizar parámetros de arranque (por ejemplo, agregar opciones al kernel) se hace editando la variable GRUB_CMDLINE_LINUX en /etc/default/grub y volviendo a correr grub-mkconfig.

Extra: dual-boot con Windows u otra distro

Para qué sirve: detectar automáticamente otros sistemas operativos instalados en discos conectados y agregarlos al menú de GRUB.

Instalar detector de otros SORIESGO BAJO 
emerge --ask sys-boot/os-prober
grub-mkconfig -o /boot/grub/grub.cfg

Detecta Windows 7/8.1/10 y otras distros de Linux automáticamente.

Alternativas a GRUB

GRUB es la opción por defecto porque es flexible (menú, parámetros editables en caliente, soporte multi-SO), pero en sistemas puramente UEFI existen alternativas más simples. Aquí es donde entra systemd-boot, que — a diferencia de GRUB — no requiere systemd como init: funciona tanto en sistemas OpenRC como systemd, porque solo necesita el paquete sys-apps/systemd-utils (versión mínima sin el init completo).

BootloaderQué esCuándo conviene
GRUB Bootloader completo con su propio menú, shell de rescate y soporte para BIOS legacy y UEFI. Puede detectar otros SO (dual-boot) y editar parámetros de arranque interactivamente antes de bootear. Es el estándar de Gentoo. Ideal si quieres flexibilidad, dual-boot, o si algo falla y necesitas un shell de rescate.
systemd-boot Un "chainloader" delgado: no tiene menú configurable ni shell propio, solo lista las entradas .conf que le pongas en la ESP y las carga directo. Funciona en OpenRC o systemd. Sistemas puramente UEFI, sin necesidad de dual-boot complejo. Arranca más rápido y es más simple de mantener. Buen soporte para Secure Boot.
EFI Stub No es un bootloader separado: el propio kernel de Linux se compila para ser directamente ejecutable por el firmware UEFI (usando la USE flag efistub). El firmware "bootea" el kernel sin intermediarios. Setups minimalistas donde no quieres ninguna capa extra. Más rígido: cambiar parámetros de arranque requiere recompilar el kernel o usar efibootmgr, no hay menú interactivo.
Comandos: instalar systemd-boot

Para qué sirve: habilitar el chainloader ligero de systemd como alternativa a GRUB, compatible con tu init OpenRC.

📍 Se configura en: /etc/portage/package.use/systemd-boot
Habilitar USE flag "boot" y compilarRIESGO BAJO 
# /etc/portage/package.use/systemd-boot
sys-apps/systemd-utils boot

emerge --ask sys-apps/systemd-utils
Instalar en la ESPRIESGO ALTO 
bootctl install
Nota para OpenRC
En sistemas con systemd se usa el paquete sys-apps/systemd; en OpenRC (tu caso) se usa sys-apps/systemd-utils, que trae solo las herramientas de boot sin instalar el init de systemd.
Comandos: arrancar el kernel como EFI Stub

Para qué sirve: eliminar la capa de bootloader por completo, dejando que el firmware ejecute el kernel directamente.

📍 Se configura en: /etc/portage/package.accept_keywords/installkernel (USE flag testing)
Habilitar soporte EFI Stub en el kernelRIESGO MEDIO 
emerge --ask sys-boot/efibootmgr

Requiere recompilar el kernel con soporte EFI Stub habilitado y la USE flag efistub en sys-kernel/installkernel (está bajo keyword testing, no es estable). Los parámetros de arranque se "incrustan" en el propio kernel vía CONFIG_CMDLINE, o se agregan como entrada de arranque con efibootmgr.

Recomendación para tu setup
Dado que ya definiste GRUB + dracut como tu stack, no necesitas cambiar nada — esta sección es solo referencia. GRUB es la opción con más margen de maniobra si algo sale mal durante el arranque (tiene shell de rescate propio), algo valioso mientras sigues aprendiendo Gentoo.
