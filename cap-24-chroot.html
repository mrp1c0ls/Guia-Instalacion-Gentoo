Cap. 24 — Chrooting

Hasta ahora todo lo hiciste "desde afuera": particionaste discos y extrajiste los archivos del sistema base (stage3) mientras seguías parado en el medio de instalación (USB/CD en vivo). En este capítulo entras a ese sistema nuevo para trabajar directamente dentro de él, como si ya estuviera instalado. A esto se le llama chroot (change root — "cambiar la raíz").

🌐 24.1 — Copiar la información de DNS

Antes de entrar, copia el archivo que le dice a tu sistema qué servidores DNS usar. Sin esto, el nuevo entorno no tendría internet aunque el cable/wifi funcione.

root # cp --dereference /etc/resolv.conf /mnt/gentoo/etc/
Para qué sirve: asegura que el sistema nuevo pueda resolver nombres de dominio (como gentoo.org) a direcciones IP. --dereference copia el archivo real (no un enlace simbólico roto) por si /etc/resolv.conf apunta a otro lugar.

📁 24.2 — Montar los sistemas de archivos necesarios

El nuevo sistema necesita "ver" ciertas carpetas especiales del kernel para funcionar. Estas no se copian, se enlazan — son literalmente las mismas que las del sistema exterior.

CarpetaQué esPor qué se necesita
/proc Sistema de archivos virtual generado al vuelo por el kernel Da información en tiempo real de procesos en ejecución (PID, memoria, CPU). Muchos programas la consultan para funcionar.
/sys Similar a /proc, pero más estructurado Expone información de hardware y dispositivos detectados por el kernel (discos, USB, red, etc.)
/dev Archivos que representan dispositivos físicos Sin esto no podrías acceder a discos (/dev/sda1), terminales, ni dispositivos aleatorios (/dev/random)
/run Almacenamiento temporal en RAM Guarda archivos de estado que solo importan mientras el sistema está encendido (PIDs de servicios, bloqueos, sockets)
root # mount --types proc /proc /mnt/gentoo/proc root # mount --rbind /sys /mnt/gentoo/sys root # mount --make-rslave /mnt/gentoo/sys root # mount --rbind /dev /mnt/gentoo/dev root # mount --make-rslave /mnt/gentoo/dev root # mount --bind /run /mnt/gentoo/run root # mount --make-slave /mnt/gentoo/run
¿Qué hacen --rbind y --make-rslave?

--rbind (bind recursivo): en vez de solo "asomarse" a una carpeta, replica también todos los sub-montajes que tiene adentro (por ejemplo, /sys/fs/cgroup suele ser su propio montaje separado). Sin la "r", esos sub-montajes quedarían invisibles dentro del chroot.

--make-rslave: por defecto, un bind mount queda conectado en ambas direcciones — lo que pase adentro del chroot también afectaría al sistema exterior. Esta opción lo vuelve de un solo sentido: los cambios de afuera se ven adentro (por ejemplo, un USB nuevo), pero lo que hagas adentro del chroot no puede romper el sistema exterior por accidente.

/run usa la versión sin "r" (--bind / --make-slave) porque normalmente no tiene sub-montajes complejos anidados.

Si usas el medio oficial de instalación de Gentoo, todo este bloque de montajes (y el paso de copiar DNS) se puede reemplazar con un solo comando:
root # arch-chroot /mnt/gentoo

Los mounts especiales se enlazan (no se copian): son literalmente los mismos que los del sistema exterior.

🚪 24.3 — Entrar al nuevo entorno

Aquí ocurre el chroot real, en tres pasos:

  1. Cambiar la raíz del sistema de / (medio de instalación) a /mnt/gentoo (tu sistema nuevo)
  2. Recargar las variables de entorno del sistema nuevo
  3. Cambiar el prompt para no perder de vista que estás "adentro"
root # chroot /mnt/gentoo /bin/bash root # source /etc/profile root # export PS1="(chroot) ${'$'}{PS1}"
Para qué sirve: a partir de este punto, cada comando que ejecutes actúa directamente sobre el sistema nuevo, no sobre el medio de instalación. Es importante ver (chroot) en tu prompt para no confundir en qué sistema estás parado.
⚠️ Importante — rutas dentro del chroot: una vez adentro, /mnt/gentoo deja de existir como tal. Lo que antes era /mnt/gentoo/efi ahora es simplemente /efi. Escribir la ruta larga desde dentro del chroot dará error de "carpeta no encontrada".
Si la instalación se interrumpe después de este punto, puedes retomarla sin volver a particionar: monta la partición raíz, copia el DNS, repite los montajes, y vuelve a entrar al chroot. Muy útil también si necesitas arreglar el bootloader más adelante.

⚙️ 24.4 — Preparando el bootloader

Ya adentro del chroot, hay que montar la partición donde vivirá el bootloader. El comando depende del tipo de firmware de tu equipo:

Tipo de sistemaParticiónSe monta enBootloader típico
UEFI (moderno)ESP, formateada en FAT32/efiGRUB (modo UEFI), systemd-boot
BIOS Legacy / MBRPartición de arranque/bootGRUB (modo Legacy)

Sistemas UEFI (GPT)

root # mkdir --parents /efi root # mount /dev/sda1 /efi
Para qué sirve: monta la ESP (EFI System Partition) donde el firmware UEFI buscará el bootloader al encender la máquina. El mkdir es necesario porque el stage3 no siempre trae la carpeta /efi creada.

Sistemas BIOS Legacy (MBR)

root # mount /dev/sda1 /boot
Para qué sirve: en un equipo con BIOS heredado (sin UEFI), no existe ESP — el bootloader (GRUB en modo Legacy) se instala directamente en el MBR del disco y sus archivos de arranque viven en /boot.
Verificación recomendada tras montar, confirma que quedó correcto antes de seguir:
root # mount | grep -E "efi|boot"
Comparación rápida: GPT+UEFI vs MBR+BIOS referencia
GPT + UEFIMBR + BIOS Legacy
Esquema de particiónGPTMBR

Punto de montaje/efi/boot

Este compendio usa GPT + UEFI, que es el estándar recomendado para equipos modernos.
