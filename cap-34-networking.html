Capítulo 34

Información de red

Cómo dejar configurada la red del sistema ya instalado: nombre del equipo, resolución de nombres local y el método de conexión (DHCP, NetworkManager o netifrc). Enfoque: OpenRC.

¿Para qué sirve este capítulo?

💡
Hasta ahora usaste la red del medio de instalación (live USB). Este capítulo configura la red que usará tu Gentoo ya instalado, la primera vez que arranque sin el USB. Si te lo saltas, el sistema instalado no tendrá internet al reiniciar.

1. Nombre del equipo (hostname)

Riesgo bajo · reversible

El hostname es el nombre que identifica tu máquina en la red local. No es una decisión permanente: se puede cambiar después sin problema.

Dónde se configura: /etc/hostname
Comando (dentro del chroot)
echo tux > /etc/hostname
🎯
Reemplaza tux por el nombre que quieras darle a tu equipo. Solo letras, números y guiones, sin espacios.

2. Archivo /etc/hosts

Riesgo bajo · reversible

/etc/hosts es una "libreta de contactos" local: traduce nombres a direcciones IP sin necesidad de un servidor DNS. Es lo primero que el sistema consulta antes de preguntarle a internet.

⚠️ En sistemas OpenRC es obligatorio que el hostname elegido en el paso anterior también aparezca aquí. Si no coincide, pueden aparecer errores o demoras al arrancar servicios.
Dónde se configura: /etc/hosts
Archivo /etc/hosts
# Debe coincidir con /etc/hostname
127.0.0.1   tux.homenetwork tux localhost
::1         tux.homenetwork tux localhost

# Opcional: otros equipos conocidos de tu red
192.168.0.5 jenny.homenetwork jenny
192.168.0.6 benny.homenetwork benny

La línea con 127.0.0.1 es IPv4 "loopback" (la máquina hablándose a sí misma); la de ::1 es lo mismo en IPv6. Ambas deben existir.

3. Elegir el método de conexión

El handbook ofrece varias formas de conectar el sistema instalado. No hay que usar más de una a la vez.

⚠️ No mezcles gestores de red. Si activas dos al mismo tiempo (por ejemplo netifrc y NetworkManager), van a pelear por controlar la misma interfaz y la red puede fallar de forma intermitente.
MétodoIdeal paraInit compatible
dhcpcdEthernet con router doméstico, IP automáticaCualquiera
NetworkManagerWiFi, laptops, escritorioCualquiera
netifrcConfiguración clásica y control finoSolo OpenRC ✅
systemd-networkdEquivalente de netifrcSolo systemd
Opción A — DHCP automático con dhcpcd rápido
Riesgo bajo
🎯
La forma más simple: tu router le asigna la IP a tu equipo automáticamente. Úsalo si no necesitas configuración especial.
Dónde se configura: nada que editar — el servicio hace todo solo.
emerge --ask net-misc/dhcpcd
rc-update add dhcpcd default

rc-update add dhcpcd default agrega el servicio al runlevel default, el conjunto de servicios que arrancan en cada boot normal.

Opción B — NetworkManager WiFi / escritorio
Riesgo bajo
🎯
Gestiona Ethernet, WiFi y PPPoE por CLI, TUI o GUI. Preferido si vas a usar un entorno de escritorio.
Dónde se configura: /etc/portage/make.conf y /etc/portage/package.use/
/etc/portage/make.conf
USE="${USE} networkmanager"
/etc/portage/package.use/networkmanager
net-wireless/wpa_supplicant dbus
emerge --ask net-misc/networkmanager
rc-update add NetworkManager default
Opción C — netifrc recomendado para tu setup OpenRC
Riesgo medio · si te equivocas de interfaz, pierdes red al reiniciar
🎯
La forma "nativa" de OpenRC. Toda la configuración vive en un solo archivo: /etc/conf.d/net. Te da control total sobre IP estática, rutas, DNS, etc.
Dónde se configura: /etc/conf.d/net

Instalar el paquete

emerge --ask --noreplace net-misc/netifrc

--noreplace evita reinstalar si ya está presente, por si viene de fábrica en el stage3.

Configurar la interfaz

nano /etc/conf.d/net
Opción 1 — DHCP
config_eth0="dhcp"
Opción 2 — IP estática
config_eth0="192.168.0.2 netmask 255.255.255.0 brd 192.168.0.255"
routes_eth0="default via 192.168.0.1"
📝 El nombre de tu interfaz real casi nunca es eth0 hoy en día (suele ser algo como enp3s0). Verifícalo antes con ip a desde el entorno live, y reemplaza eth0 por ese nombre en todo el proceso.

Activar la red al arrancar

cd /etc/init.d
ln -s net.lo net.eth0
rc-update add net.eth0 default

¿Por qué un symlink? net.lo es un script genérico de OpenRC que sabe leer /etc/conf.d/net y aplicar la configuración según el nombre con el que se le invoque. Al enlazarlo como net.eth0, ese mismo script configurará específicamente esa interfaz. Si tienes varias interfaces, repites el enlace para cada una (net.wlan0, etc.).

Si te equivocaste de nombre de interfaz tras reiniciar

  1. Corrige el nombre en /etc/conf.d/net
  2. Crea el nuevo enlace simbólico correcto
  3. Borra el enlace viejo: rm /etc/init.d/net.eth0
  4. Agrega el nuevo al runlevel: rc-update add net.enpXsY default
  5. Quita el viejo: rc-update del net.eth0 default
Opción D — systemd-networkd solo si usas systemd
No aplica a tu instalación (usas OpenRC) · referencia
🎯
Es el equivalente de netifrc pero para systemd. Se configura con archivos .network en estilo INI.
Dónde se configura: /etc/systemd/network/*.network
/etc/systemd/network/50-dhcp.network
[Match]
Name=en*

[Network]
DHCP=yes
systemctl enable systemd-networkd.service

4. Conceptos de red que conviene entender

CIDR — ¿qué significa el "/24"?

CIDR indica cuántos bits de la dirección IP pertenecen a la red y cuántos al host. Es la notación tipo 192.168.0.2/24.

  • /24 → 254 direcciones utilizables (el tamaño más común en redes domésticas)
  • /32 → 1 sola dirección (un host individual)

Fórmula: 2^(32 − CIDR) − 2 direcciones utilizables (se restan la dirección de red y la de broadcast).

Gateway / ruta por defecto

El gateway (puerta de enlace) es el dispositivo — normalmente tu router — que reenvía tu tráfico hacia fuera de la red local, hacia internet. Es lo que le dice a tu equipo "todo lo que no sea de esta red, mándamelo a mí".

# Ver rutas actuales
ip route

# Agregar ruta por defecto manualmente
ip route add default via 192.168.0.1
DNS — traducir nombres a IPs

El DNS traduce nombres de dominio (gentoo.org) a direcciones IP. Se configura en /etc/resolv.conf.

/etc/resolv.conf
nameserver 1.1.1.1
nameserver 1.0.0.1
⚠️ Si dhcpcd está corriendo, sobrescribirá este archivo automáticamente y tus cambios manuales no persistirán. Verifica con ps x | grep dhcpcd.

Diagnóstico por capas: si un nivel falla, el problema está ahí (no en los de arriba).

5. Verificar que todo funciona

# Ver interfaces y direcciones asignadas
ip a

# Ver tabla de rutas
ip r

# Probar conectividad y resolución DNS
ping -c 3 gentoo.org

Si el ping responde, tienes conectividad e internet funcionando correctamente.

Resumen de tu ruta (OpenRC)

  1. echo tux > /etc/hostname
  2. Reflejar el mismo nombre en /etc/hosts
  3. emerge --ask --noreplace net-misc/netifrc
  4. Configurar /etc/conf.d/net (DHCP o IP estática)
  5. Crear el symlink y activar en el runlevel: rc-update add net.eth0 default
  6. Verificar con ip a y ping
