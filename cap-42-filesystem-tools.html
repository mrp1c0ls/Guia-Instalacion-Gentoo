Capítulo 42 — Herramientas de Sistemas de Archivos

Filesystem tools: qué son, para qué sirven y cómo instalarlas correctamente antes de continuar con el bootloader.

Idea central del capítulo: ya creaste tus particiones y les diste formato (con mkfs.xfs, mkfs.ext4, etc.). Pero formatear no es lo mismo que mantener. Este capítulo trata sobre instalar las herramientas de administración de cada filesystem — las que usarás después, ya con el sistema arrancado, para revisar, reparar o redimensionar tus particiones.

¿Para qué sirve esto?

Cada tipo de filesystem (XFS, ext4, btrfs, etc.) es en realidad un formato de datos distinto en el disco, y cada uno tiene su propio conjunto de programas para administrarlo: revisar errores, reparar corrupción, agrandar o achicar la partición, ver estadísticas de uso, etc. El kernel sabe leer y escribir esos formatos, pero las tareas de mantenimiento las hacen programas de espacio de usuario (userspace), no el kernel.

Si no instalas el paquete correspondiente, tu sistema instalado se quedará sin herramientas de mantenimiento para su propio disco — por ejemplo, no podrás correr un fsck si algo se corrompe después de un apagón.

Analogía con NixOS: es como declarar boot.supportedFilesystems en tu configuration.nix. No basta con que el kernel soporte el filesystem — también necesitas los paquetes de utilidades correspondientes instalados para poder administrarlo día a día.

Punto clave: ext4 ya viene incluido

Las herramientas de ext4 (sys-fs/e2fsprogs) ya están instaladas por defecto en cualquier sistema Gentoo, porque forman parte del @system set — el conjunto mínimo de paquetes que Portage considera imprescindibles. Si tu partición raíz es ext4, no tienes que hacer nada en este capítulo.

Para cualquier otro filesystem (XFS, btrfs, VFAT, F2FS, NTFS, ZFS), sí tienes que emergerlo tú mismo, dentro del chroot, antes de reiniciar.

El comando

RIESGO BAJO — es solo instalar paquetes, totalmente reversible

El patrón general es siempre el mismo:

emerge --ask sys-fs/<paquete-correspondiente>

Por ejemplo, si tu raíz es XFS:

root # emerge --ask sys-fs/xfsprogs

¿En dónde se ejecuta esto?

Todavía estás dentro del chroot (el sistema nuevo, no el live environment). No hay ningún archivo de configuración que editar en este capítulo — es puramente instalar el paquete correcto vía Portage.

Profundizando: qué hace cada herramienta y sus opciones más usadas

xfsprogs (XFS) — comandos y opciones útiles

Para qué sirve: XFS es el filesystem recomendado por el handbook para uso general moderno. xfsprogs trae todo lo necesario para crearlo, revisarlo y mantenerlo.

  • mkfs.xfs — crea el filesystem (ya lo usaste en el capítulo de discos).
  • xfs_repair /dev/sdaX — repara corrupción. Importante: la partición debe estar desmontada.
  • xfs_growfs / — agranda el filesystem en caliente (con el sistema montado) después de expandir la partición subyacente. XFS no se puede achicar.
  • xfs_info / — muestra información técnica del filesystem (tamaño de bloque, geometría, etc.).
e2fsprogs (ext4) — comandos y opciones útiles

Para qué sirve: conjunto de herramientas para ext2/ext3/ext4. Ya viene instalado por defecto.

  • e2fsck -f /dev/sdaX — revisa y repara. La opción -f fuerza el chequeo aunque el filesystem se vea "limpio".
  • resize2fs /dev/sdaX — agranda o achica el filesystem (a diferencia de XFS, ext4 sí se puede achicar, pero solo desmontado).
  • tune2fs -l /dev/sdaX — muestra parámetros configurados (UUID, label, intervalos de chequeo automático, etc.).
dosfstools (VFAT/FAT32) — comandos y opciones útiles

Para qué sirve: necesario para administrar tu partición EFI (/efi), que obligatoriamente es FAT32 por especificación UEFI.

  • fsck.vfat -a /dev/sdaX — revisa y repara automáticamente (-a = auto-fix sin preguntar).
  • fatlabel /dev/sdaX NOMBRE — cambia la etiqueta de la partición.
Relevante para tu instalación: ya que usas GPT + UEFI, tu partición /efi depende de este paquete. Aunque técnicamente no es obligatorio tenerlo instalado en el sistema final (el kernel puede montarlo sin problema), sí lo necesitas si algún día quieres reparar o redimensionar esa partición.
btrfs-progs, f2fs-tools, ntfs3g, zfs — solo si aplica

Estos no aplican a tu configuración actual (XFS/ext4 + FAT32), pero se dejan documentados para referencia:

  • btrfs-progs: btrfs check, btrfs balance (redistribuye datos entre discos), btrfs subvolume (crea subvolúmenes tipo snapshot).
  • f2fs-tools: pensado para memorias flash (USB, microSD). fsck.f2fs, resize.f2fs.
  • ntfs3g: ntfsfix repara errores básicos; no reemplaza chkdsk de Windows para reparaciones profundas.
  • zfs: administración por pools, no por partición individual — zpool status, zpool scrub (verifica integridad de datos con checksums).

¿Aplica systemd aquí?

No. Este capítulo es agnóstico al sistema de init — emerge y las herramientas de filesystem funcionan exactamente igual bajo OpenRC o systemd, porque son utilidades de Portage/kernel, no servicios. La diferencia OpenRC/systemd solo aparece cuando se trata de automatizar chequeos (por ejemplo, systemd tiene unidades fstrim.timer para SSDs vía systemctl enable fstrim.timer; en OpenRC eso se haría con un cronjob).

Extra: recomendación adicional del handbook

Si tu disco es un SSD/NVMe, el handbook recomienda instalar sys-block/io-scheduler-udev-rules para que el sistema use el planificador de E/S correcto automáticamente: 

root # emerge --ask sys-block/io-scheduler-udev-rules

Checklist rápido antes de avanzar al capítulo 43

  • ✅ ¿Tu raíz es ext4? → no hay nada que hacer.
  • ✅ ¿Tu raíz es XFS u otro? → corre emerge --ask sys-fs/<paquete>.
  • ✅ ¿Vas a mantener tu /efi a futuro? → considera dosfstools si no lo tienes.
