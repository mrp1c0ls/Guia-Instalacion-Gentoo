Capítulo 11 — Conceptos básicos de Internet e IP

Teoría de redes necesaria para entender (y arreglar a mano) la conexión durante la instalación.

Teórico Riesgo: ninguno No requiere comandos obligatorios
Para qué sirve este capítulo: si la red no se configuró sola (DHCP, NetworkManager, etc.), este capítulo te da el vocabulario y la lógica para configurarla tú mismo a mano en el siguiente capítulo.

1. Interfaces y direcciones

Una interfaz es simplemente el nombre lógico que el sistema le da a un dispositivo de red (tu tarjeta ethernet o WiFi). Para poder hablar con otros equipos necesita al menos una dirección IP asignada, aunque puede tener varias a la vez (por ejemplo IPv4 e IPv6 juntas).

⚠️ Las IPs se pueden poner "a mano" libremente, así que si dos equipos usan la misma por error, hay un conflicto de direcciones. Por eso se prefiere que se asignen solas mediante:

ProtocoloSe usa enQué hace
DHCPIPv4Un servidor de la red le reparte una IP libre automáticamente
SLAACIPv6El propio dispositivo se autoconfigura una dirección sin servidor

2. Redes y CIDR

Una vez que tienes una dirección, el sistema necesita saber qué otras direcciones están "cerca" de ti, es decir, en tu misma red local. Eso se expresa con la notación CIDR: un número después de una barra que indica el tamaño de la red.

Ejemplo

192.168.0.2/24 se traduce así:

Tu dirección192.168.0.2
Red a la que perteneces192.168.0.0
Tamaño útil254 equipos (192.168.0.1 – 192.168.0.254)
Dirección de broadcast192.168.0.255
¿Cómo se calcula el tamaño de una red? (fórmula)

Tamaño = 2 ^ (32 − CIDR), y luego se le restan 2 direcciones (la de red y la de broadcast, que no se pueden usar en un equipo normal).

Los valores CIDR más comunes son /24 (254 equipos, típico de una red doméstica) y /32 (un solo equipo).

3. Internet: el router y la puerta de enlace

Para hablar con algo fuera de tu red local necesitas un router, que reenvía tu tráfico hacia afuera. La dirección de ese router dentro de tu red se llama default route o gateway (puerta de enlace). Por convención suele ser la primera o la última IP disponible de la red (ej. 192.168.0.1).

Interfaz con IP + CIDR→ Habla con la red local→ Envía lo externo al gateway→ Internet

4. El sistema de nombres de dominio (DNS)

Recordar direcciones IP es incómodo, así que el DNS traduce nombres de dominio (como gentoo.org) a la IP real. En Linux, los servidores DNS que se van a usar se definen en el archivo:

/etc/resolv.conf
Dato útil: muchos routers también hacen de servidor DNS. Usar uno local (el del router o uno propio) suele acelerar las consultas gracias al caché, y mejora algo la privacidad.

Comandos de verificación

Aunque el capítulo es teórico, se apoya en dos comandos ya vistos para comprobar que todo lo anterior funciona:

root # ping -c 3 1.1.1.1

Para qué sirve: confirma que hay conectividad básica a Internet, probando contra una IP directa (sin depender del DNS).

root # curl --location gentoo.org --output /dev/null

Para qué sirve: prueba dos cosas a la vez: que el DNS resuelve el nombre y que la salida HTTPS funciona.

➕ Extra para enriquecer: cómo leer un error rápido
SíntomaDiagnóstico probable
ping 1.1.1.1 fallaNo hay conectividad de red real: revisa cable/WiFi, interfaz e IP
ping 1.1.1.1 funciona, pero curl gentoo.org fallaEl DNS no está resolviendo — revisa /etc/resolv.conf
Ambos funcionanLa red está lista, puedes continuar con la instalación
➕ Extra: IPv4 vs IPv6, en una frase

IPv4 usa direcciones tipo 192.168.0.2 (4 números) y suele configurarse con DHCP; IPv6 usa direcciones más largas tipo fe80::ea40:f2ff... y normalmente se autoconfigura sola con SLAAC — casi nunca hace falta tocarla a mano.
