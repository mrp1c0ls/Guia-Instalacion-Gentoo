Limpieza de disco

Eliminación de artefactos de instalación tras un reboot exitoso
¿Para qué sirve este capítulo?

Una vez que tu sistema Gentoo ya arrancó correctamente fuera del chroot, los archivos que usaste para construir el sistema (el stage3 y sus acompañantes de verificación) ya cumplieron su propósito. Este capítulo es simplemente recoger la basura que dejó el proceso de instalación en el directorio raíz.

1. ¿Qué son estos "artefactos de instalación"?

Cuando descargaste e instalaste el stage3 (capítulo de instalación del stage), dejaste varios archivos en /:

  • stage3-amd64-*.tar.xz — el tarball con el sistema base que extrajiste.
  • *.DIGESTS / *.CONTENTS — archivos con los checksums (SHA256/BLAKE2B) que usaste para verificar que el tarball no estuviera corrupto o alterado.
  • *.asc — la firma PGP del tarball, usada para confirmar que el archivo lo publicó realmente el equipo de Gentoo.

Ninguno de estos archivos es necesario para que el sistema funcione — son evidencia del proceso de instalación, no parte del sistema instalado.

Analogía rápida

Es como cuando instalas un programa desde un .exe o .deb descargado: una vez instalado, el instalador ya no hace falta. Puedes borrarlo sin que el programa deje de funcionar.

2. Requisito previo Importante

Este paso se hace después de reiniciar y confirmar que el sistema Gentoo bootea correctamente (capítulo 48, "Rebooting the system"). No lo hagas dentro del entorno live ni antes de comprobar que el arranque fue exitoso — si algo salió mal con GRUB o el kernel, es útil conservar el stage3 por si necesitas volver a chroot y reparar algo.

3. Verificar qué hay antes de borrar Riesgo bajo

Es buena práctica ver primero qué archivos existen, en vez de borrar a ciegas:

# Lista archivos en la raíz que empiecen con "stage3"
root # ls -lh /stage3-*
Ejecutas ls -lh /stage3-*. El shell expande el patrón (glob) y te muestra cada archivo que coincide, junto con su tamaño en formato legible (-h).
Confirmas visualmente que ahí está el .tar.xz y sus archivos de verificación asociados (.DIGESTS, .asc, etc.).

4. Eliminar los artefactos

root # rm /stage3-*.tar.*
El shell expande /stage3-*.tar.* a todos los archivos en / que empiecen con stage3- y contengan .tar. en el nombre (esto cubre el .tar.xz mismo y variantes como .tar.xz.asc o .tar.xz.sha256).
rm borra cada archivo de la lista resultante, uno por uno, sin pedir confirmación (comportamiento por defecto de rm sin la flag -i).
El espacio en disco se libera inmediatamente — el stage3 suele pesar varios cientos de MB, así que es una limpieza notoria.
Opciones útiles de rm si quieres más control
OpciónQué hace
-iPregunta confirmación antes de borrar cada archivo.
-vModo verboso: imprime cada archivo que borra.
-fFuerza el borrado sin preguntar, ignora archivos inexistentes.

Ejemplo más seguro para primera vez: rm -iv /stage3-*.tar.*

5. Confirmar que se liberó espacio (opcional)

root # df -h /

df -h (disk free, formato legible) muestra el espacio usado y disponible en cada sistema de archivos montado. Correrlo antes y después del rm te deja ver la diferencia real.

6. Enriquecimiento: no lo confundas con la limpieza de Portage

Este capítulo borra archivos sueltos de instalación, algo que se hace una sola vez. Es distinto de la limpieza continua que hace Portage sobre paquetes ya emergidos (vista en el capítulo 49, "Portage maintenance"):

ComandoQué limpiaFrecuencia
rm /stage3-*.tar.*El tarball de instalación inicial y sus firmas/checksums.Una sola vez, tras el primer reboot exitoso.
emerge --depcleanPaquetes huérfanos que ya no dependen de nada instalado.Periódica, tras actualizaciones.
eclean-distTarballs de código fuente viejos en /var/cache/distfiles (requiere app-portage/gentoolkit).Periódica.
eclean-pkgPaquetes binarios viejos en /var/cache/binhost/gentoo.Periódica.
systemd vs OpenRC

Este capítulo no tiene diferencias entre init systems — rm y df son comandos de shell estándar, no dependen de OpenRC ni systemd. Como usas OpenRC, no aplica ninguna variante aquí.
