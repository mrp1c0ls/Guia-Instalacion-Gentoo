¿Qué es installkernel?

Es el paquete que actúa como repartidor automático del kernel. Cuando más adelante emerjas el kernel de verdad (capítulo 32), alguien tiene que:

  • Copiar la imagen del kernel a /boot o /efi (según el bootloader)
  • Generar el initramfs si hace falta
  • Avisarle al gestor de arranque que hay un kernel nuevo

Ese trabajo lo hace installkernel, y su comportamiento se define antes de instalar el kernel, mediante USE flags.

Para qué sirve este capítulo: no instala el kernel — solo prepara el mecanismo que lo va a "enganchar" correctamente con tu bootloader e initramfs cuando lo instales en el siguiente capítulo.

¿Dónde se configura?

Todo pasa por archivos dentro de /etc/portage/package.use/, que es un directorio, no un archivo único. Portage lee todos los archivos que haya adentro y los combina.

Archivo (nombre libre, por convención)Contenido
/etc/portage/package.use/installkernelsys-kernel/installkernel grub dracut
/etc/portage/package.use/ukiFlags relacionadas a Unified Kernel Image (opcional)

Si el archivo aparece vacío al abrirlo con nano, es normal: lo estás creando tú mismo, no viene pre-poblado como make.conf.

31.1 Bootloader — elegir el mecanismo de arranque DECISIÓN

Esta es la decisión más importante del capítulo: define quién arranca tu kernel al encender la máquina. No instala nada del bootloader todavía (eso es el capítulo 44) — solo le dice a installkernel para cuál de ellos debe preparar los archivos.

OpciónQué esUSE flagsCopia el kernel a
GRUB El más flexible y documentado. Funciona en BIOS y UEFI. Recomendado si no estás seguro. grub /boot
systemd-boot Más simple, solo UEFI. Funciona con OpenRC o systemd. Buen soporte de Secure Boot. systemd systemd-boot /efi
EFI stub El kernel arranca directo desde el firmware UEFI, sin intermediario. Minimalista pero rígido. efistub (testing) /efi
Tradicional (lilo, syslinux) Layout clásico de /boot, para bootloaders antiguos o no-UEFI. ninguno de los anteriores /boot
¿Por qué "solo una selección es necesaria"?

Porque cada opción configura installkernel para hablar con un bootloader distinto. Elegir GRUB y systemd-boot al mismo tiempo no tiene sentido — son mecanismos que compiten entre sí, no que se complementan. Puedes cambiar de opinión después reinstalando installkernel con otras flags.

Para qué sirve la flag grub específicamente: hace que cada vez que se instale un kernel nuevo, se ejecute automáticamente grub-mkconfig por ti — sin ese flag tendrías que regenerar la configuración de GRUB a mano cada vez.

31.2 Initramfs CASI SIEMPRE NECESARIO

Es un mini sistema de archivos temporal en RAM que carga los módulos necesarios (por ejemplo, el driver de tu disco) antes de que el kernel pueda montar tu partición raíz real.

Para qué sirve: sin él, si tu driver de almacenamiento es un módulo (lo normal en un kernel de distribución), el kernel arranca pero no encuentra cómo montar /, y el sistema no bootea. 
# /etc/portage/package.use/installkernel
sys-kernel/installkernel dracut
emerge --ask sys-kernel/installkernel

31.3 Unified Kernel Image (opcional) OPCIONAL

Empaqueta kernel + initramfs + parámetros de arranque en un solo archivo. Útil sobre todo para Secure Boot, porque firmas un solo archivo en vez de varios.

¿Debería usarlo en mi primera instalación?

No es necesario. Añade complejidad extra y está pensado para casos con Secure Boot activo. Se puede agregar después, una vez que el sistema arranque de forma confiable con la configuración básica.

✅ Configuración recomendada (GRUB + OpenRC + dracut)

# /etc/portage/package.use/installkernel
sys-kernel/installkernel grub dracut
emerge --ask sys-kernel/installkernel

Este comando no instala el kernel — instala la herramienta que sabrá qué hacer cuando lo emerjas en el capítulo 32.

Preguntas frecuentes

¿Y si no configuro nada, funciona igual?

installkernel se instala de todas formas como dependencia del kernel, pero sin las USE flags correctas puede quedar sin generar initramfs ni avisar al bootloader. El sistema podría quedar instalado sin poder arrancar. No es obligatorio en todos los casos, pero en tu configuración (kernel de distribución + GRUB) prácticamente sí lo es.

¿Por qué el archivo package.use/installkernel aparece vacío al abrirlo?

Porque lo estás creando tú. A diferencia de make.conf (que ya viene con contenido del stage3), los archivos dentro de package.use/ normalmente no existen hasta que tú decides que un paquete necesita una excepción.

¿El nombre del archivo dentro de package.use/ importa?

No. Portage lee todos los archivos de esa carpeta y los combina como si fueran uno. El nombre installkernel es solo convención para que tú sepas qué contiene cada archivo.

¿Puedo elegir GRUB y systemd-boot a la vez "por si acaso"?

No tiene sentido — son mecanismos de arranque distintos y competirían entre sí. Elige uno; siempre puedes cambiar después reconfigurando installkernel.

¿Este capítulo ya instala GRUB?

No. Solo prepara installkernel para que sepa que, cuando GRUB esté instalado (capítulo 44), debe generar su configuración automáticamente. La instalación real de GRUB en el disco es un paso posterior y de mayor riesgo.
