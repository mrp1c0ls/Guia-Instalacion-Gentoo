Capítulo 41 — Sincronización de tiempo

Gentoo Handbook · Configuración recomendada: chrony + OpenRC

¿Por qué importa este paso? Tu sistema necesita saber la hora exacta. Sin ella, la verificación de certificados HTTPS falla, los paquetes descargados pueden parecer "corruptos" por errores de fecha, y los logs quedan desordenados. Se corrige sincronizando contra servidores de internet vía el protocolo NTP (Network Time Protocol).

1. El problema que resuelve

Hay dos escenarios donde esto se necesita:

  • Sin RTC funcional (reloj de hardware de la placa madre): el sistema debe fijar la hora en cada arranque, siempre.
  • Con RTC: igual conviene, porque la pila del RTC puede fallar o el reloj se desfasa ("clock skew") con el tiempo.

2. Opción recomendada: chrony

Es la implementación de NTP que sugiere el handbook. Corre en segundo plano como un servicio (daemon) llamado chronyd, que consulta servidores de tiempo confiables y ajusta tu reloj de forma gradual y suave, sin saltos bruscos que rompan procesos en ejecución.

⚠️ No confundir: chrony (sincroniza el reloj) vs cronie (Cap. 37, ejecuta tareas programadas). Suenan parecido, son cosas distintas.
Instalar chronyriesgo bajo · reversible
root # emerge --ask net-misc/chrony
Para qué sirve: descarga e instala el paquete. "Emerger" solo lo agrega a tu sistema, no cambia nada en el arranque todavía.

2.1 Activarlo — OpenRC tu configuración

Añadir al runlevel defaultriesgo bajo
root # rc-update add chronyd default
Para qué sirve: le dice a OpenRC que arranque chronyd automáticamente cada vez que enciendes la máquina, en el runlevel normal (default). Es el mismo patrón que ya usaste con sshd o cronie.

2.2 Activarlo — systemd

Habilitar el servicioriesgo bajo
root # systemctl enable chronyd.service
Para qué sirve: equivalente exacto a rc-update add pero en el mundo systemd — registra el servicio para que systemd lo lance al iniciar.
Configuración y uso de chrony (para enriquecer)

El archivo de configuración vive en /etc/chrony/chrony.conf. Ahí defines qué servidores NTP usar, por ejemplo:

pool 2.gentoo.pool.ntp.org iburst

Una vez corriendo, se administra con la herramienta de línea de comandos chronyc:

ComandoQué hace
chronyc trackingMuestra el estado actual de sincronización (desfase, precisión)
chronyc sourcesLista los servidores NTP configurados y su calidad de conexión
chronyc makestepFuerza un ajuste inmediato si el desfase es grande

También existe el modo puntual, útil justo durante la instalación (ya lo usaste en el capítulo de configuración inicial):

root # chronyd -q

Esto sincroniza una sola vez y termina, sin quedar como servicio corriendo.

3. Alternativa: systemd-timesyncd

Solo disponible si usas systemd como init system (no aplica a tu instalación con OpenRC). Es un cliente SNTP más simple y liviano que chrony — ya viene instalado por defecto en sistemas systemd, solo hay que activarlo:

Habilitar systemd-timesyncdriesgo bajo
root # systemctl enable systemd-timesyncd.service
Para qué sirve: activa el sincronizador ligero integrado en systemd. No requiere instalar ningún paquete aparte.
¿Dónde se configura systemd-timesyncd?

En /etc/systemd/timesyncd.conf, sección [Time], con la directiva NTP= para especificar servidores. Se consulta el estado con:

$ timedatectl timesync-status

🔁 Analogía NixOS: similar a declarar services.chrony.enable = true; en configuration.nix. En Gentoo el proceso es imperativo: primero emerge instala el paquete, luego rc-update add lo "activa" explícitamente para el arranque.

5. Resumen ejecutable (tu caso: OpenRC)

Los dos únicos comandos que necesitasriesgo bajo
root # emerge --ask net-misc/chrony
root # rc-update add chronyd default
